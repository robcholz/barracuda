A profile names the Plugins a firmware contains. Every Board builds one
profile: the one its `board.yml` names, or `headless` when it names none.
A Plugin that no profile and no Board enables is not in the firmware at all:
no code, no settings, no text.

The rules (how the enabled set is computed, what fails, the local override)
are in [`plugin-api.md`](/architecture/plugin-api#enablement-per-board).
This page says which profiles exist and how to pick or add one.

## The profiles

The profiles are layers. Each one adds Plugins to the ones it extends, and
the dependencies of every listed Plugin come along on their own.

| Profile | Extends | Adds | Network | Lua |
| --- | --- | --- | --- | --- |
| `minimal` | — | workflows, time, the scheduler, power, sound | no | no |
| `lua` | `minimal` | the VM and the Lua packages that need no network, among them those for the Board's hardware | no | yes |
| `network` | `minimal` | Wi-Fi, the web server, the captive portal, HTTP, the portal's file manager | yes | no |
| `ai` | `network` | the Agent, its tools, and the message gateways | yes | no |
| `connected` | `lua`, `network` | the Lua packages that need the network but not the Agent: HTTP and the web server | yes | yes |
| `headless` | `connected`, `ai` | the Lua packages that need the Agent | yes | yes |
| `ui` | — | the app manager with the system UI, the system fonts, the Files and Workflows apps | no | yes |
| `screen-offline` | `lua`, `ui` | nothing more | no | yes |
| `screen-connected` | `connected`, `ui` | Wi-Fi in the system UI, the Settings app | yes | yes |
| `screen` | `headless`, `screen-connected` | the Sessions app | yes | yes |

```text
                 minimal
                /       \
             lua         network
              | \        /    |
              |  connected    ai
              |    |     \    |
              |    |     headless               (the default)
              |    |         |
              |  screen-connected = connected + ui + …
              |          \   |
              |          screen = headless + screen-connected + …
              |
       screen-offline = lua + ui
```

A profile without Wi-Fi builds no radio either: the `wifi` Plugin is the one
that takes the Platform's radio, so without it an ESP firmware links no Wi-Fi
driver, radio firmware, or network task, and its IP stack has no link.

`ui` is a layer, not a product: it has no Lua packages for the hardware and
no way online. A Board with a screen names `screen`, `screen-connected`, or
`screen-offline`.

`connected` and `screen-connected` are `headless` and `screen` without the
Agent: online, with Lua scripts that make and serve HTTP requests, but
without the Agent, its tools, the message gateways, or the Sessions app.
They are for Boards whose flash cannot hold the Agent. Their names say what
sets them apart from `lua` and `screen-offline`: the device goes online.

`screen-offline` has no Settings or Sessions app: Settings depends on Wi-Fi
and Sessions on the Agent. Volume and brightness are in the control center.

## Picking one

A Board names its profile in `board.yml`:

```yaml
profile: screen-offline
plugins:
  camera:
    enabled: false
```

- A product with a screen names `screen`, `screen-connected` when its flash
  cannot hold the Agent, or `screen-offline` when it never goes online.
- A product without one names nothing and builds `headless`, or a narrower
  layer: `connected` when its flash cannot hold the Agent, `minimal`, `lua`,
  `network`, or `ai`.
- One Plugin more or less goes in `plugins.<id>.enabled` on the Board, not in
  a new profile.

## Fitting the flash

The firmware has to fit the Board's app slot (see
[ESP flash layout](/boards/overview#esp-flash-layout)): 2816 KiB on 4 MiB of
flash. On the ESP32 it also has to fit the 3 MiB and 192 KiB the chip maps for
code. Release builds of `headless` take about 4 MiB on the ESP32-C3, ESP32-C6,
and ESP32-S3, and `screen` about 5 MiB on the ESP32-S3; on the ESP32,
`headless` overflows the code window. On the ESP32, `connected` takes about
2.3 MiB and `screen-connected` about 3.1 MiB, more than a 4 MiB Board's slot,
so a 4 MiB ESP32 Board with a screen builds `screen-offline`. The STM32U5A5
runs from a 2.5 MiB flash region, which `headless` overflows by about 227 KiB.
So the Boards build:

| Chip | Flash | Without a screen | With a screen |
| --- | --- | --- | --- |
| ESP32 | 4 MiB | `connected` | `screen-offline` |
| ESP32 | 8 MiB, 16 MiB | `connected` | `screen-connected` |
| ESP32-C3 | 4 MiB | `connected` | — |
| ESP32-C6 | 4 MiB | `connected` | — |
| ESP32-C6 | 8 MiB, 16 MiB | `headless` | `screen` |
| ESP32-S3 | 8 MiB, 16 MiB | `headless` | `screen` |
| ESP32-P4 | 16 MiB | `headless` | `screen` |
| STM32U5A5 | 4 MiB | `connected` | — |

## Adding one

A new profile is a file here. Name it for what the product does, extend the
layers it builds on, and list only what it adds:

```yaml
# boards/profiles/gateway.yml
extends: network
enable:
  - agent
  - imessage-gateway
  - imessage-telegram
```

`extends` takes one profile or a list; a profile reached twice counts once,
and a profile that extends itself fails. `enable` only adds: a narrower
product extends a narrower layer instead of removing Plugins.

Run `cargo plugin sync` after changing a profile or a Board, and
`cargo plugin sync --check` before committing.
