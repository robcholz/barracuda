The ESP32-P4-Function-EV-Board is an ESP32-P4 Board from Espressif.

- Board ID: `esp32p4-function-ev-board`
- Vendor: Espressif
- Chip: ESP32-P4
- Platform: [ESP32](/platforms/esp32)
- Rust target: `riscv32imafc-unknown-none-elf`
- Profile: [`headless`](/boards/profiles) (the default)
- Flash layout: `boards/configs/esp32p4-function-ev-board/partitions.csv`

## Build and run

```bash terminal
cargo board select esp32p4-function-ev-board
cargo run
cargo image deploy
```

Install the toolchain first; see [ESP32](/platforms/esp32).

## Peripherals

This Board declares no peripherals yet. The network, the Agent, and the
portal run on it; add its devices to
`boards/configs/esp32p4-function-ev-board/board.yml` to drive them. See
[Peripheral composition](/boards/peripherals).

## Wired Ethernet

The Board's IP101GRI PHY is declared under `hardware.ethernet` in its
`board.yml`, and the [ESP32-P4 Platform](/platforms/esp32) runs the IP stack
over it: the EMAC on the RMII pads, the PHY at address 1 with its reset on
`GPIO51`, and a DHCP client. Plug in a cable and the console logs
`network is up at <address>`; the portal answers there on port 8787.

`GPIO35`, the BOOT button, is RMII TXD1: the button is unusable while Ethernet runs.

| Signal | Pin |
| --- | --- |
| Reference clock in (from the PHY) | `GPIO50` |
| MDC / MDIO | `GPIO31` / `GPIO52` |
| TX_EN / TXD0 / TXD1 | `GPIO49` / `GPIO34` / `GPIO35` |
| CRS_DV / RXD0 / RXD1 | `GPIO28` / `GPIO29` / `GPIO30` |
| PHY reset | `GPIO51` |

## Wi-Fi

The Wi-Fi radio is the ESP32-C6-MINI-1 co-processor, declared under
`hardware.wifi-coprocessor` in `board.yml`. It runs Espressif's factory
ESP-Hosted-MCU firmware, version 0.0.6 according to the ESP-Hosted
documentation. The Platform resets the co-processor and talks to it over SDIO
at 40 MHz. The [Wi-Fi Plugin](/plugins/wifi) opens its setup hotspot on the
co-processor.

| Signal | Pin |
| --- | --- |
| SDIO CLK / CMD | `GPIO18` / `GPIO19` |
| SDIO D0 / D1 / D2 / D3 | `GPIO14` / `GPIO15` / `GPIO16` / `GPIO17` |
| Co-processor reset | `GPIO54` |

If the co-processor does not start, or runs firmware the Platform cannot
drive, the console logs `Wi-Fi is unavailable: <reason>` and the Board keeps
Ethernet alone.

## Two links, one IP stack

The Board has one IP stack over both links. The stack uses Ethernet while the
cable's link is up and the Wi-Fi station otherwise. Each switch makes it
restart DHCP, so the device's address changes with the link. The console logs
`network is up at <address>` for each address it gets.

## Plugin settings

- [`imessage-gateway`](/plugins/imessage-gateway) `receive-slots` is `0`: no
  connections are reserved for channel receive loops on this Board.
