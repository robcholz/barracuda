The M5Stack Tab5X is an ESP32-P4 Board from M5Stack.

- Board ID: `m5stack-tab5x`
- Vendor: M5Stack
- Chip: ESP32-P4
- Platform: [ESP32](/platforms/esp32)
- Rust target: `riscv32imafc-unknown-none-elf`
- Profile: [`screen`](/boards/profiles)
- Flash layout: `boards/configs/m5stack-tab5x/partitions.csv`

## Build and run

```bash terminal
cargo board select m5stack-tab5x
cargo run
cargo image deploy
```

Install the toolchain first; see [ESP32](/platforms/esp32).

## Peripherals

| Device | What it is | Lua package |
| --- | --- | --- |
| `audio-codec` | Audio codec (ES8388 speaker DAC, ES7210 microphone ADC) | [`audio`](/plugins/vm-audio) |
| `display` | 720x1280 MIPI DSI display (ILI9881C, ST7123, or ST7121, detected at start) | [`display`](/plugins/vm-display) |
| `touch` | Touch controller (GT911 or the panel's ST712x) | — |
| `real-time-clock` | Real-time clock (RX8130CE) | — |
| `inertial-measurement` | Motion sensor (BMI270) | [`motion`](/plugins/vm-imu) |
| `power-monitor` | Power monitor (INA226) | [`power_monitor`](/plugins/vm-power-monitor) |

The display implementation resets the panel and the touch controller through
the PI4IOE5V6408 expander at `43h`, which is not a device of its own. As M5GFX
does, it holds the touch interrupt line (GPIO23) high meanwhile, so a GT911
answers at `14h`, and then identifies the panel by the touch controller that
answers.
The audio codec implementation switches the speaker amplifier on through the
same expander. The microSD slot is not declared yet: it is on slot 0 of the
SD host, whose slot 1 the Platform drives for the Wi-Fi co-processor, and the
Platform cannot yet hand slot 0 to a Board device. The SC202CS camera is not
declared either: the ESP32-P4 Platform has no MIPI CSI binding.

## Exposed pins

Lua scripts open these pins by name.

| Name | Pin |
| --- | --- |
| `port-a-scl` | `GPIO54` |
| `port-a-sda` | `GPIO53` |
| `port-b-g17` | `GPIO17` |
| `port-b-g52` | `GPIO52` |
| `port-c-g6` | `GPIO6` |
| `port-c-g7` | `GPIO7` |
| `rs485-rx` | `GPIO21` |
| `rs485-tx` | `GPIO20` |
| `rs485-dir` | `GPIO34` |

`rs485-tx`, `rs485-rx`, and `rs485-dir` are the UART and direction pins of the
on-board RS485 transceiver.

```lua
local gpio = require("gpio")
local pin = gpio.open_input("port-a-scl", "up")
print(pin:read())
```

## Wi-Fi

The Wi-Fi radio is the ESP32-C6 co-processor, declared under
`hardware.wifi-coprocessor` in `board.yml`. It runs M5Stack's factory
ESP-Hosted-MCU firmware. The [ESP32-P4 Platform](/platforms/esp32) does the
following at startup:

1. Switches on the co-processor's power through output 0 of the PI4IOE5V6408
   expander at `44h`.
2. Resets the co-processor.
3. Talks to it over SDIO at 40 MHz.

The IP stack runs on its Wi-Fi station, and the
[Wi-Fi Plugin](/plugins/wifi) opens its setup hotspot on the co-processor.
When a network gives the device an address, the console logs
`Wi-Fi is up at <address>`.

| Signal | Pin |
| --- | --- |
| SDIO CLK / CMD | `GPIO12` / `GPIO13` |
| SDIO D0 / D1 / D2 / D3 | `GPIO11` / `GPIO10` / `GPIO9` / `GPIO8` |
| Co-processor reset | `GPIO15` |
| Co-processor power | PI4IOE5V6408 `44h` output 0 on `I2C0` (`GPIO32` / `GPIO31`) |

The factory firmware version has not been checked against this host on a
device. If the co-processor does not start, or runs firmware the Platform
cannot drive, the console logs `Wi-Fi is unavailable: <reason>`. The Board
then has no network link and no setup hotspot.

## Plugin settings

- [`imessage-gateway`](/plugins/imessage-gateway) `receive-slots` is `0`: no
  connections are reserved for channel receive loops on this Board.
