The website is a static Next.js site in `website/`, in English at `/` and in
Chinese at `/zh/`. Run it locally:

```bash terminal
cd website
bun install
bun run dev
```

Open [http://localhost:3000](http://localhost:3000). `bun run build` writes
the static site to `website/out/`.

## Where things are

| Path | Holds |
| --- | --- |
| `src/content/en.tsx`, `src/content/zh.tsx` | Every word on the site. Change both languages in the same pull request |
| `src/content/boards.ts` | The boards page's list: one entry per Board in `boards/configs/` |
| `src/components/` | The pages, built from the design system's components |
| `src/styles/ds/` | The design system's `tokens.css` and `bundle.css`, copied from the design system unchanged |
| `src/styles/site.css` | The website's own layout, on the design system's tokens |
| `public/images/` | The painting, the brand logos, and the board figure |
| `src/content/repo.ts` | The Platform, Plugin and channel counts the home page quotes, generated from the repository |
| `src/components/Installer.tsx`, `src/components/InstallerSteps.tsx` | The browser installer at `/install/`: its flow and its six steps |
| `src/content/install-en.ts`, `src/content/install-zh.ts` | The installer's words, kept apart from the site's because they hold functions |
| `src/lib/install/` | The installer's logic: release archives, flash layout, console lines, releases, and flashing |
| `public/install/` | The installer's board figures, light and dark |

Links to the docs and to Live Editor go through `src/lib/links.ts`, so every
page links to them in the reader's language. Every install button opens the
installer.

## The installer

`/install/` and `/zh/install/` flash ESP Boards from desktop Chrome or Edge;
[Installation](/get-started/installation) walks a visitor through it. It works
without a server:

- The version list and release notes come from the GitHub Releases API, which
  allows cross-site reads.
- The release archives do not allow cross-site reads, so the visitor downloads
  one and drops it back on the page. The page unpacks it in the browser and
  checks its `manifest.json`: the Board, the version, and every part's SHA-256.
- `esptool-js` connects over Web Serial, checks the chip and its flash size,
  reads the partition table and the app descriptor to tell whether Barracuda
  is already on the Board, and writes the parts.
- After the restart, the page reads the Board's `BARRACUDA wifi=…` console
  lines to follow Wi-Fi setup to the portal's address.

What a release holds is in [Releases](/contributing/releases).

## Rules

- Draw with the design system's components (`bc-*`) and tokens. A component the
  website and the docs both need belongs in the design system; copy its new
  `tokens.css` and `bundle.css` into `src/styles/ds/`, then run
  `bun tools/web/docs-tokens.ts` so the docs follow.
- Adding a Board adds its entry to `src/content/boards.ts`. `bun test tools/web`
  fails while the list and `boards/configs/` differ, or a listed Board has no
  docs page.
- The home page's counts come from `src/content/repo.ts`. After adding or
  removing a Platform or a Plugin, regenerate it; `bun test tools/web` fails
  while it is out of date:

  ```bash terminal
  bun tools/web/website-repo.ts
  ```

## Deploy

Vercel builds the site from this repository:

- **Root Directory**: `website`
- **Framework Preset**: Next.js (detected)
- **Production branch**: `master`
- **Include files outside the Root Directory in the Build Step**: on, the default

Every push to `master` deploys the site, and every pull request gets a preview
link.

The site also serves [Live Editor](/apps/live-editor) at `/editor/`.
`vercel.json` runs `apps/live-editor/web/build-site.sh public/editor` before
`next build`, which installs Rust and PocketJS on the build machine and builds
Live Editor into `public/editor/`; that directory is not committed. A local
`bun run build` leaves Live Editor out. See
[Live Editor internals](/tools/live-editor#deploy) for what the script does.
