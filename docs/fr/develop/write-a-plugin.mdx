---
title: "Écrire un Plugin"
description: "Ajoutez une capacité à Barracuda avec votre agent de code et la skill create-plugin."
---

Chaque capacité de Barracuda est un Plugin : en ajouter un est donc la façon
d’étendre le runtime. Faites-le sur votre ordinateur, dans le dépôt, avec
l’agent de code que vous utilisez déjà : Claude Code, Cursor ou Codex.

## Demander à votre agent de code

Le dépôt fournit une skill `create-plugin` dans
`.agents/skills/create-plugin/SKILL.md`. Elle applique pas à pas le contrat de
l’[API des Plugins](/architecture/plugin-api) : le résultat ressemble donc à
tous les Plugins intégrés.

```txt
> Lis .agents/skills/create-plugin/SKILL.md, puis crée un Plugin qui
  lit un capteur de température et d’humidité SHT40 et l’expose à Lua.
```

## Ce que fait la skill

<Steps>
  <Step title="Définir la portée">
    Nommez la fonctionnalité dont le Plugin est propriétaire et les Plugins dont
    il utilise les capacités. Ceux-ci, et seulement ceux-ci, deviennent son
    `depends-on`.
  </Step>
  <Step title="Organiser le répertoire">
    Créez `plugins/<id>/plugin.toml` et `crates/plugin`, activez le Plugin dans
    un profil ou sur une carte, et lancez `cargo plugin sync`.
  </Step>
  <Step title="Construire, enregistrer et démarrer">
    Un seul constructeur, `new(&mut PluginContext)`. Enregistrez les contrats
    dans `register` ; lancez les tâches possédées dans `start`.
  </Step>
  <Step title="Ajouter les contrats dont les appelants ont besoin">
    Une capacité typée pour les autres Plugins, des actions et événements
    Workflow, un paquet Lua via un Plugin `vm-<name>`, ou un outil de l’Agent via
    un Plugin `agent-<name>`.
  </Step>
  <Step title="Tester et documenter">
    Des tests ciblés pour le Plugin, et sa page `docs/plugins/<id>.mdx` dans la
    forme requise.
  </Step>
</Steps>

## Vérifier le résultat

```bash terminal
cargo plugin info <id>     # manifest and dependencies
cargo plugin sync --check  # conventions, and the generated registry is current
```

`cargo plugin sync` vérifie d’abord que chaque Plugin respecte les conventions :
son organisation, ses schémas, la forme de sa page et les dépendances de ses
crates. Lancez localement les tests ciblés du Plugin ; laissez la matrice de
tests complète à la CI.
