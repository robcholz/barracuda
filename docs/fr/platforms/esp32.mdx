Les puces Espressif exécutent Barracuda sur cinq plateformes bare-metal, une
par puce. Elles partagent un outil de flashage, `espflash`, et un plan de la
flash, une table de partitions ESP-IDF dans le `partitions.csv` de chaque carte.
Elles diffèrent par la cible Rust et la chaîne d’outils : `esp` est la chaîne
d’outils Rust d’Espressif, et RISC-V GCC est le GCC `riscv32-esp-elf`
d’Espressif.

| Puce (plateforme) | Cible Rust | Chaîne d’outils | Cartes |
| --- | --- | --- | --- |
| ESP32 (`esp32`) | `xtensa-esp32-none-elf` | `esp` 1.98.1.0 | 24 |
| ESP32-S3 (`esp32s3`) | `xtensa-esp32s3-none-elf` | `esp` 1.98.1.0 | 36 |
| ESP32-C3 (`esp32c3`) | `riscv32imc-unknown-none-elf` | Rust 1.98.1, RISC-V GCC | 5 |
| ESP32-C6 (`esp32c6`) | `riscv32imac-unknown-none-elf` | Rust 1.98.1, RISC-V GCC | 5 |
| ESP32-P4 (`esp32p4`) | `riscv32imafc-unknown-none-elf` | `esp` 1.98.1.0, RISC-V GCC | 7 |

## Installer la chaîne d’outils

Installez `espup` une fois, puis la chaîne d’outils de votre puce.
`cargo board select` affiche la même commande quand la chaîne d’outils manque.

<Tabs>
  <Tab title="ESP32, ESP32-S3">
    ```bash terminal
    cargo install espup
    espup install --toolchain-version 1.98.1.0
    ```
  </Tab>
  <Tab title="ESP32-C3, ESP32-C6">
    ```bash terminal
    rustup toolchain install 1.98.1
    cargo install espup
    espup install --stable-version 1.98.1 --targets esp32c3 --esp-riscv-gcc
    ```

    Pour l’ESP32-C6, utilisez `--targets esp32c6`.
  </Tab>
  <Tab title="ESP32-P4">
    ```bash terminal
    cargo install espup
    espup install --toolchain-version 1.98.1.0 --targets esp32s3,esp32p4 --esp-riscv-gcc
    ```

    `espup` installe la chaîne d’outils `esp` avec une cible Xtensa : la
    commande nomme donc aussi `esp32s3`.
  </Tab>
</Tabs>

`espup` écrit `~/export-esp.sh`. La sélection de la carte l’importe : vous
n’avez pas à le sourcer vous-même. Installez `espflash` pour flasher :

```bash terminal
cargo install espflash
```

<Note>
  La plateforme ESP32-S3 reste sur `esp` 1.98.1.0 : la version 1.99.0.0
  réordonne le code de démarrage d’esp-hal, si bien que les compilations en mode
  release ne passent plus l’édition de liens.
</Note>

## Compiler, flasher et exécuter

```bash terminal
cargo board select m5stack-cores3
cargo run
cargo image deploy
```

- `cargo run` compile le firmware avec `--release`, le flashe avec
  `espflash flash --monitor` et garde le journal série dans le terminal.
- `cargo image deploy` compile l’image de ressources des Plugins et l’écrit dans
  la partition `resources` avec `espflash write-bin`.

## Matériel piloté par les plateformes

Chaque plateforme ESP32 fournit des entrées et sorties numériques, le GPIO, des
périphériques SPI, des bus SPI, des sorties SPI et des périphériques I2C. Les
E/S à l’exécution permettent aux scripts Lua de réserver ces contrôleurs sur les
broches exposées d’une carte :

| Plateforme | I2C | SPI | UART | ADC |
| --- | --- | --- | --- | --- |
| `esp32` | `I2C0`, `I2C1` | `SPI2`, `SPI3` | `UART1` | `ADC1` |
| `esp32s3` | `I2C0`, `I2C1` | `SPI2`, `SPI3` | `UART1` | `ADC1` |
| `esp32p4` | `I2C0`, `I2C1` | `SPI2`, `SPI3` | `UART1` | `ADC1` |
| `esp32c3` | `I2C0` | `SPI2` | `UART1` | `ADC1` |
| `esp32c6` | `I2C0` | `SPI2` | `UART1` | `ADC1` |

L’ESP32-S3 ajoute les périphériques quad SPI, les cartes SD/MMC, la capture
caméra, les flux audio I2S et le tactile capacitif.
