---

La plateforme Linux exécute la même `embassy_net::Stack` que les plateformes
d’appareil et connecte son pilote simulé de couche trois à une véritable
interface TUN Linux persistante.

Provisionnez la TUN, le routage et le NAT une fois par démarrage :

```sh
sudo sh platforms/linux/provision.sh barracuda0
```

L’application ouvre ensuite `barracuda0` sans privilèges root.

```sh
cargo board select local-linux
BARRACUDA_VIRTUAL_IO_ADDR=127.0.0.1:7878 cargo run
```

`BARRACUDA_VIRTUAL_IO_ADDR` est obligatoire : c’est l’adresse de bouclage où
écoute le gestionnaire de périphériques virtuels. `local-linux` expose les
broches virtuelles `vio-0` à `vio-7` et deux contrôleurs I2C virtuels ; le
gestionnaire pilote les niveaux d’entrée, branche des périphériques I2C et
injecte des pannes. Consultez [`platforms/virtual-io`](/platforms/virtual-io).

Ce terminal possède le System et ses journaux. Lancez `cargo cli` dans un autre
terminal pour connecter le canal terminal externe.

- pair côté système d’exploitation : `10.42.0.1/30`
- pile Embassy Net : `10.42.0.2/30`, où écoutent les services de l’appareil

Les journaux de la plateforme, du System, du Core et des Plugins sont écrits sur
la sortie d’erreur standard au niveau `info`. Choisissez un autre niveau pour
une compilation avec, par exemple, `BARRACUDA_LOG_LEVEL=debug cargo run`.
