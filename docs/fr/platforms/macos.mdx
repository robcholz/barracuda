---
title: "Plateforme macOS"
sidebarTitle: "macOS"
description: "Exécutez Barracuda sur macOS via une passerelle réseau en espace utilisateur non privilégiée, sans `sudo`."
---

La plateforme macOS exécute la même `embassy_net::Stack` que les plateformes
d’appareil et connecte son pilote de couche trois à la passerelle non
privilégiée en espace utilisateur de Barracuda. Elle ne crée pas d’interface
UTUN, ne modifie pas les règles PF, n’active pas le routage sur l’hôte et ne
demande pas `sudo`.

- pile invitée : `10.0.2.15/24`
- passerelle virtuelle : `10.0.2.2`
- DNS virtuel : `10.0.2.3`
- transport des paquets : `ws://127.0.0.1:8787/v1/connect`

Sélectionnez la carte macOS et suivez le flux de travail habituel :

```sh
cargo board select local-macos
cargo build
BARRACUDA_VIRTUAL_IO_ADDR=127.0.0.1:7878 cargo run
```

`BARRACUDA_VIRTUAL_IO_ADDR` est obligatoire : c’est l’adresse de bouclage où
écoute le gestionnaire de périphériques virtuels (n’importe quel port libre
autre que le 8787 de la passerelle). `local-macos` expose les broches virtuelles
`vio-0` à `vio-7` et deux contrôleurs I2C virtuels. Consultez
[`platforms/virtual-io`](/platforms/virtual-io).

`cargo run` compile le lanceur de la plateforme, déploie l’image System
sélectionnée, démarre la passerelle réseau de bouclage, puis l’application
System. Le lanceur possède les deux processus : Ctrl-C ou SIGTERM arrête donc
l’exécution complète. Aucun second terminal ni aucune commande manuelle de
passerelle n’est nécessaire.

La passerelle relaie le TCP et l’UDP émis par l’appareil via des sockets
ordinaires de l’hôte, traduit les requêtes DNS envoyées à `10.0.2.3` et associe
une URL de bouclage au port TCP invité configuré. La plateforme macOS journalise
cette URL à l’ouverture de la session et la publie dans `.barracuda/address`. La
CLI découvre l’adresse active depuis ce fichier : un port de bouclage éphémère
n’a donc pas à être copié dans la configuration locale. Son sélecteur
Local/Remote affiche l’adresse Local découverte avant de se connecter.
`cargo cli configure` utilise le même sélecteur et ouvre le portail de
configuration des Plugins du System actif.

Les journaux de la plateforme, du System, du Core et des Plugins sont écrits sur
la sortie d’erreur standard au niveau `info`. Choisissez un autre niveau pour
une compilation avec, par exemple, `BARRACUDA_LOG_LEVEL=debug cargo run`.
