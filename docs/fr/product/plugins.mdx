Tout ce qu’un appareil Barracuda sait faire vient d’un Plugin. Le runtime
lui-même est petit : un System portable qui enregistre les Plugins dans l’ordre
des dépendances et les démarre ensemble. Personnaliser un appareil, construire
dessus et l’étendre revient toujours à choisir, configurer, alléger ou écrire
des Plugins.

## Ce qu’est un Plugin

Un Plugin est une unité autonome dotée d’une identité stable et d’un contrat
déclaré.

- **Identité et dépendances.** Un `plugin.toml` donne au Plugin son ID, les
  Plugins dont il dépend et ses tâches de compilation.
- **Capacités typées.** Un Plugin peut fournir des API de domaine à d’autres
  Plugins et exiger les leurs. C’est ainsi que les Plugins collaborent
  directement.
- **Actions et événements Workflow.** Un Plugin peut exposer des opérations et
  des faits aux automatisations Workflow, avec des contrats stables et vérifiés
  par schéma.
- **Outils de l’Agent.** Un Plugin peut donner de nouvelles capacités à l’Agent
  embarqué via des outils conçus pour les agents et destinés au modèle.
- **Paquets VM.** Un Plugin peut exposer du matériel ou des services aux
  scripts, afin que le code en temps réel de l’Agent embarqué puisse les
  utiliser.
- **Une page de portail.** Un Plugin peut ajouter sa propre page, son icône et
  son état au portail de l’appareil : chaque capacité arrive avec ses propres
  réglages.
- **Ressources et stockage.** Un Plugin possède ses fichiers, ses réglages et
  ses tâches de longue durée, et les libère quand il s’arrête.
- **Documentation.** Chaque Plugin documente ses capacités, outils, actions,
  événements, erreurs et cycle de vie dans son propre `docs/plugin.md`, écrit
  pour les humains et pour les agents.

## Pourquoi une brique de base

- **Une seule façon d’ajouter quoi que ce soit.** Un pilote de capteur, un canal
  de messagerie, un fournisseur de recherche web et l’agent lui-même sont tous
  des Plugins. Il n’y a pas de second mécanisme d’extension à apprendre.
- **Composables.** Les Plugins dépendent des capacités des autres, pas de leurs
  détails internes : on peut donc les combiner librement.
- **Amovibles.** Un Plugin non activé n’est pas embarqué. Retirer un Plugin
  libère sa mémoire, sa flash et ses tâches.
- **Portables.** Les Plugins dépendent de services portables, jamais d’une puce
  particulière : le même Plugin tourne sur toutes les plateformes.
- **Adaptés aux agents.** Le contrat est assez explicite pour qu’un agent le
  lise, l’utilise et l’écrive. L’Agent embarqué appelle les outils des Plugins ;
  les agents de code créent des Plugins avec la skill `create-plugin`.

## Le catalogue de Plugins

| Famille | Exemples |
| --- | --- |
| Appareil | Provisionnement Wi-Fi et point d’accès de configuration, serveur web, portail de l’appareil, client HTTP, heure, planificateur |
| Agent | L’Agent embarqué, recherche web, fichiers, HTTP pour les agents, planifications, accès à Workflow, accès à la VM |
| Canaux | WeChat, Telegram, QQ, iMessage, Inkbox, chat web, terminal |
| Automatisation | Workflow, planificateur |
| Scripts | La VM et ses paquets |
| Périphériques | GPIO, analogique, I2C, I2S, SPI, UART, PWM, écran, caméra, audio, IMU, bande de LED, mesure de consommation, système de fichiers, file de messages, informations système |
| Applications | App Manager et le runtime d’applications |

## Personnaliser avec les Plugins

| Qui | Comment ils personnalisent |
| --- | --- |
| Utilisateurs et makers | Choisissent l’ensemble de Plugins sur leur machine et compilent ; configurent chaque Plugin dans le portail de l’appareil |
| Développeurs d’applications | Utilisent les Plugins depuis leurs applications via le Live Editor |
| Développeurs de Plugins | Créent de nouveaux Plugins avec `create-plugin` |
| Concepteurs de produits | Choisissent l’ensemble exact de Plugins d’un produit et allègent chaque Plugin selon le budget de la cible avec `fully-customize` |

## S’adapter aux ressources

Barracuda tourne sur des microcontrôleurs dotés de quelques centaines de
kilo-octets de RAM, sur des cartes avec mémoire externe et sur des hôtes de
bureau. L’ensemble de Plugins est le principal levier pour s’adapter à une
cible :

- les petites cibles embarquent l’essentiel : le réseau, le portail, l’agent, la
  VM, un canal ;
- les cibles plus grandes ajoutent des périphériques, d’autres canaux, des
  applications et des scripts concurrents ;
- un firmware de produit embarque exactement ce dont le produit a besoin, et
  rien d’autre.
