description: "L’Agent embarqué, l’Agent du navigateur et les agents de code sur votre machine : ce que fait chacun et pourquoi."

Barracuda place l’IA à trois endroits. Chacun est choisi pour le travail qu’il
fait le mieux, et chacun utilise les Plugins comme unité de capacité.

|  | Agent embarqué | Agent du navigateur | Agents de code sur la machine |
| --- | --- | --- | --- |
| Vit | Sur l’appareil | Dans le Live Editor | Sur la machine du développeur (Claude Code, Cursor, Codex) |
| Intervient | À l’exécution | À la compilation | À la compilation |
| Fait | Codage en temps réel : écrit des scripts VM qui pilotent le matériel immédiatement | Développement d’applications : génère les applications de l’appareil et leur interface | Crée des Plugins, des cartes, des plateformes ; compose un firmware entièrement sur mesure |
| Poids | Léger, limité par l’appareil | Lourd, modèle complet et contexte complet | Lourd, dépôt complet et chaîne d’outils |
| Produit | Un script qui s’exécute immédiatement | Une application flashée sur l’appareil | Du code source qui devient firmware |
| Niveaux de l’échelle | 1 | 3 | 4, 5, 6 |

## L’Agent embarqué — le codage en temps réel

L’Agent embarqué s’exécute sur l’appareil en tant que Plugin Agent. Il possède
les sessions, la mémoire, les plans, les sous-agents, les skills et les outils ;
seule l’inférence du modèle est un appel distant — vers un fournisseur de
modèles configuré par l’utilisateur, ou vers le service de modèles de
Barracuda. Les utilisateurs le joignent par n’importe quel canal : WeChat,
Telegram, QQ, iMessage, le chat web de l’appareil ou le terminal.

Sa capacité phare est le **codage en temps réel**. Quand une demande touche le
monde physique, l’agent écrit un court script Lua et l’exécute dans la VM de
l’appareil. Les paquets VM exposent le matériel — GPIO, I2C, SPI, UART, PWM,
entrées analogiques, écrans, caméras, audio, IMU, bandes de LED, mesure de
consommation —, si bien que le script lit et pilote de vrais périphériques dès
son exécution. Les scripts peuvent demander une saisie à l’utilisateur en cours
d’exécution, signaler leur progression, et être listés ou annulés. Un script
peut à son tour poser une question à l’agent : un programme en cours
d’exécution peut donc raisonner lui aussi.

Pour un comportement qui doit survivre à une conversation, l’agent utilise les
automatisations et les planifications Workflow : « tous les matins à sept
heures », « quand le bouton est pressé », « quand la température dépasse
30 °C ».

**Pourquoi il est volontairement léger.** L’appareil dispose d’un budget mémoire
fixe et d’un petit nombre d’emplacements d’exécution. Le rôle de l’Agent
embarqué n’est pas de construire du logiciel ; c’est d’agir — vite, en sécurité
et de façon visible — avec ce que l’appareil possède déjà. Tout ce qui est plus
gros passe à la compilation.

## L’Agent du navigateur — le développement d’applications

L’Agent du navigateur vit dans le Live Editor. Le développeur décrit une
application ; l’agent génère sa logique et son interface, et le développeur
l’affine dans un aperçu visuel en direct. Une fois prête, le navigateur la
flashe sur l’appareil par USB.

Sur l’appareil, les applications sont gérées par le Plugin App Manager et
s’exécutent dans le runtime d’applications aux côtés de tous les autres
Plugins. Une application utilise les Plugins de l’appareil via les mêmes
contrats que le reste du système : elle peut donc utiliser l’écran, les
capteurs, le réseau et l’Agent embarqué.

**Pourquoi le navigateur.** La génération d’applications profite d’un grand
modèle, d’un grand contexte et d’une boucle visuelle : générer, prévisualiser,
ajuster. Le navigateur offre les trois, sans installation, et il détient déjà
la connexion USB utilisée pour le flashage.

## Les agents de code sur la machine — Plugins, cartes, plateformes, firmware

La création de code du runtime — Plugins, cartes, plateformes et firmware sur
mesure — se fait sur la machine du développeur, dans le dépôt Barracuda, avec
l’agent de code qu’il utilise déjà : Claude Code, Cursor ou Codex.

Barracuda fournit des **skills** pour ces agents. Une skill décrit la façon dont
Barracuda est construit, afin que l’agent travaille à la manière de Barracuda :

| Skill | Ce que l’agent en fait |
| --- | --- |
| `create-plugin` | Crée ou met à jour un Plugin : choisit des capacités typées, des actions et événements Workflow ou des outils de l’Agent ; câble le cycle de vie et la propriété des tâches ; écrit les schémas, la documentation et des tests ciblés |
| `create-board` | Ajoute une carte sur une plateforme existante : puce, cible, plan de la flash, périphériques |
| `create-platform` | Démarre une nouvelle famille de puces derrière le contrat de plateforme sans modifier le System ni les Plugins |
| `fully-customize` | Sélectionne ou crée la plateforme et la carte, choisit et allège les Plugins, crée ceux qui manquent et adapte le firmware aux ressources de la cible |

**Pourquoi la machine.** Ce travail exige l’arborescence source complète, la
chaîne d’outils native, la compilation, les tests et souvent le matériel posé
sur le bureau. Cet environnement, c’est la machine du développeur, et les
meilleurs agents pour lui sont les agents de code auxquels les développeurs font
déjà confiance.

## Comment les trois travaillent ensemble

- **En descendant l’échelle :** le firmware sur mesure d’un concepteur est livré
  avec l’Agent embarqué ; une application créée dans le Live Editor peut appeler
  l’Agent embarqué ; un Plugin créé sur la machine devient disponible pour les
  scripts, les applications et le portail de l’appareil.
- **En montant l’échelle :** un script qui valide une idée sur l’appareil devient
  une application dans le Live Editor ; une application qui a besoin d’une
  capacité absente du runtime devient un Plugin ; un Plugin qui a besoin d’un
  nouveau matériel devient une carte.
- **Un seul contrat en dessous :** les trois agents passent par les contrats des
  Plugins — outils de l’Agent sur l’appareil, interfaces d’application dans
  l’éditeur, et contrats de Plugin, de carte et de plateforme dans le dépôt. Ce
  contrat partagé permet au travail de passer de l’un à l’autre.
