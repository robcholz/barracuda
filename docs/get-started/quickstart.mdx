---
title: "Quickstart"
description: "Run Barracuda on your computer, connect a model, and ask the Agent to drive a pin."
---

Run the same System a device runs, on Linux or macOS, with virtual peripherals
in place of hardware. Then connect a model and talk to the on-board Agent.

<Info>
  Prerequisites: Rust installed and the repository cloned. See
  [Installation](/get-started/installation). You also need an API key for an
  OpenAI or Anthropic model service.
</Info>

<Steps>
  <Step title="Select a host Board">
    ```bash terminal
    cargo board select local-linux   # or local-macos
    ```

    Host Boards build the `screen` profile: the Agent, Lua scripts, web chat,
    the portal, and a virtual round display.
  </Step>
  <Step title="Prepare the network (Linux only)">
    The Linux Platform uses a real TUN interface. Provision it once per boot:

    ```bash terminal
    sudo sh platforms/linux/provision.sh barracuda0
    ```

    macOS needs no setup and no `sudo`.
  </Step>
  <Step title="Run Barracuda">
    ```bash terminal
    BARRACUDA_VIRTUAL_IO_ADDR=127.0.0.1:7878 cargo run
    ```

    This terminal owns the System and its logs. `BARRACUDA_VIRTUAL_IO_ADDR` is
    where the virtual peripherals listen; open
    [http://127.0.0.1:7878/](http://127.0.0.1:7878/) to see the display.
  </Step>
  <Step title="Connect a model">
    In a second terminal, start the configurator, choose **Local**, then the
    **Models** (`agent`):

    ```bash terminal
    cargo cli configure
    ```

    Answer the prompts: the API format (`openai` or
    `anthropic`), the purpose `root_agent`, the base URL, the model,
    and your API key. The key is stored on the device. You can do the same on
    the **Models** page of the [Device Portal](/use/device-portal).
  </Step>
  <Step title="Talk to the Agent">
    Open the terminal channel and choose **Local**:

    ```bash terminal
    cargo cli
    ```

    Ask for something physical:

    ```txt
    > Set pin vio-0 high
    ```

    The Agent writes a short Lua script, runs it with its `vm_run` tool, and
    replies with the result. The host Boards expose the virtual pins `vio-0`
    to `vio-7`.
  </Step>
</Steps>
