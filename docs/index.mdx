Barracuda is a plugin-based embedded runtime and an agentic platform. Every
capability on a device is a Plugin, and every step of building for a device is
done together with an agent. The same `no_std` System runs on ESP32 and STM32
microcontrollers and on Linux and macOS; the Board and the Platform are selected
independently.

## The ladder

Each level is useful on its own, and each one gives more freedom than the one
below it. The docs follow the same levels.

| Level | What you do | Where | Who helps |
| --- | --- | --- | --- |
| 01 · Out of the box | Install, then ask the board to do things | Browser, phone, device | The on-board agent writes and runs scripts |
| 02 · Configure | Choose the Plugins in the firmware, build, flash | Your computer | A command, a file, or your coding agent |
| 03 · Build apps | Describe an app, get its logic and UI, install it | Browser and device | The in-browser agent |
| 04 · Create Plugins | Add a capability to the runtime | Your computer | Coding agent with `create-plugin` |
| 05 · Boards and Platforms | Bring up a new board or chip family | Your computer | Coding agent with `create-board`, `create-platform` |
| 06 · Fully customize | Fit a firmware to a chip and a resource budget | Your computer | Coding agent with `fully-customize` |

## Three agents

Light work happens on the device, at run time. Heavy work happens in the browser
and on your computer, at build time. All three work through Plugin contracts.

| | Where it runs | When | What it does | What it produces |
| --- | --- | --- | --- | --- |
| On-board agent | On the device, as the [Agent](/plugins/agent) Plugin | Run time | Writes Lua scripts and runs them against the hardware | A script that runs now |
| In-browser agent | In the browser | Build time | Generates apps and their UI | An app on the device |
| Coding agents | Your computer: Claude Code, Cursor, Codex | Build time | Creates Plugins, Boards, Platforms, custom firmware | Source code built into firmware |

See [Three agents](/product/three-agents) for how they hand work to each other.

## Four layers

Read these four and you can read the repository.

| Layer | Owns | Directory |
| --- | --- | --- |
| Board | YAML for the chip, toolchain target, flash layout, peripherals, and Plugin profile | `boards/` |
| Platform | Executor entry, network stack, filesystem, flash, and HAL adapters | `platforms/` |
| System | The `no_std` aggregation layer that registers every Plugin in dependency order, then starts them | `core/system/` |
| Plugins | Typed capabilities, Workflow Actions and Events, Agent Tools, portal pages, runtime tasks | `plugins/` |

The [repository layout](/architecture/repository) and
[platform architecture](/architecture/platform-architecture) pages go deeper.

<Tip>
  No board? Select `local-linux` or `local-macos`. The same System runs on your
  computer, with peripherals simulated by [Virtual IO](/platforms/virtual-io).
</Tip>
