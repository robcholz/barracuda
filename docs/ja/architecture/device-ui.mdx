Barracuda のデバイス UI は、**システム**、**システムアプリ**、**インストール可能なアプリ** の 3 つのレイヤーで構成されます。すべての画面、ジェスチャー、アプリはこのうちちょうど 1 つに属し、レイヤーによって、誰が所有するか、何をしてよいか、失敗したときにどうなるかが決まります。このドキュメントは、この区分についての正式な定義です。各画面の設計はデバイス UI のデザインに、契約は各プラグインのドキュメントにあります。

| | システム | システムアプリ | インストール可能なアプリ |
| --- | --- | --- | --- |
| 正体 | `app-manager` プラグイン内のネイティブな Rust | 組み込みアプリ: 別のプラグインが同梱するアプリコンテナ | 利用者がインストールしたアプリコンテナ |
| 置き場所 | `app-manager` プラグインの `/resources/view` | 対応する `builtin-app-<name>` プラグインの `/resources/app` | `app-manager` プラグインの `/media/apps/<id>` |
| 実行形態 | `app-manager` のタスク | アプリのライフサイクルのもとで、MicroTS のビューを持つ Lua の実行 | 同上 |
| Lua パッケージ | なし | 登録されたすべてのパッケージ（自身のパッケージを含む） | アンビエントのパッケージと、マニフェストで指定したもの。組み込みアプリのパッケージは使えません |
| 削除 | 不可 | 不可。アプリ情報のみ。ボードがそのプラグインを外すことはできます | 可能。アプリ情報とアンインストール |
| 失敗したとき | デバイスが壊れた状態になります | システムがアプリの終了を表示します | 同上 |
| 例 | ホームと Agent の状態表示、ランチャー、スイッチャー、通知センターとコントロールセンター、起動中、終了、インストール、アプリメニューとアプリ情報 | Sessions、Workflows、Files、Settings | 空気質、ライトストリップ、カメラ、カウンターのサンプル |

## プラグイン

| プラグイン | 内容 |
| --- | --- |
| `app-manager` | アプリキット（アプリ、インストール、ライフサイクル、`app` パッケージ）、UI キット（ビュー、ディスプレイ、タッチ、ジェスチャー、システムフォントとアイコン）、そしてこれらをつないでシステム UI を動かすエントリーポイント |
| `builtin-app-<name>` | 1 つのシステムアプリ。そのコンテナと、独自の Lua パッケージのバックエンド |
| `system-fonts` | ディスプレイ上のすべてのビューが描画に使うシステムフォント |
| `system-wifi` | システム UI での Wi-Fi。`app-manager` の `SystemNetwork` を通じて、接続状態、オフラインカード、ポータルのタイルが開くセットアップ用ホットスポットを提供します |

アプリキットはディスプレイを必要としません。ディスプレイのないボードでは、`app-manager` プラグインは UI キットもシステム UI も動かさず、ヘッドレスアプリのためのアプリマネージャーとして動きます。ビューを持つアプリは `no_display` を返します。システム UI はネットワークも必要としません。`system-wifi` のように、プラグインが `SystemNetwork` でネットワークを表示する場合にだけ、ネットワークを表示します。画面のあるボードは `screen` プロファイルを指定します。オンラインに出ることのない製品（Wi-Fi、ポータル、Agent、Sessions、Settings なし）では `screen-offline` を指定します。どちらも `ui` レイヤー、つまり `app-manager`、`system-fonts`、ネットワークを必要としない組み込みアプリを含みます。プロファイルについては [ボードプロファイル](/ja/boards/profiles) を参照してください。ボードは、プラグインを有効にしないことでシステムアプリを外せます。ディスプレイのないボードは、システムアプリも `system-fonts` も有効にしません。

## レイヤーの決め方

次のいずれかに当てはまる機能は **システム** に置きます。

- アプリがハングまたはクラッシュしたとき、あるいはアプリが動いていないときにも機能する必要がある。
- アプリ間の調停を行う。ディスプレイに何を表示するか、どのアプリを前面に出すか、どのアプリを動かすかなど。
- 信頼を与える。インストール、アンインストール、アプリが使ってよいものなど。
- どこでも有効な入力に応える。画面端からのスワイプ、戻る操作、システム画面での長押し、ボードのホームキーと Agent キーなど。

デバイスに同梱される全画面の体験で、インストール可能なアプリでは許可なしに取得できないデバイスの状態を必要とし、失敗してもデバイス全体を巻き込まないものは **システムアプリ** にします。Settings、会話、Workflows、ファイルなどです。

それ以外はすべて **インストール可能なアプリ** です。ポータル、Agent、または別のプラグインによって Workspace で提示され、利用者がインストールします。

## システム

`app-manager` プラグインのシステム UI がシステムです。利用者に代わってアプリの切り替えとアンインストールを行う唯一の呼び出し元であり、システムジェスチャーの唯一の所有者です。また、デバイスのセットアップ用ホットスポット上にある `app-portal` プラグインのポータルページと並んで、利用者がアプリをインストールする唯一の手段です。そのビューはアプリレイヤーの上にあるシステムレイヤーに置かれます。アプリが前面にあり、システム画面に覆われていない間はアプリのビューが表示されます。システム画面がアプリを覆うと、その画面が閉じるまでアプリへの入力が止まります（`AppManager::set_interactive`）。

UI キットはタッチを、ディスプレイ上のビューを押すタップと、システムにだけ届く長押しとスワイプに変換します（`UiService::next_gesture`）。アプリはシステムジェスチャーを受け取らないので、利用者が抜け出す手段をアプリが奪うことはできません。

お知らせはシステムの通知センターを通じて利用者に届きます。どのプラグインも `Notifications` ケイパビリティで、Workflow は `app.notify` で通知センターに投稿できます。利用者の回答が必要な質問（`Notifications::ask`、`app.confirm`）は先頭に並び、回答されるまでホーム画面に表示されます。ホーム画面には、`AgentStatus` または `app.agent` から得た Agent の状態（待機中、聞き取り中、考え中、回答中）も表示されます。アプリが他のアプリやシステムの上に描画することはありません。

デバイスの設定（明るさ、音量、ミュート、マイク、おやすみモード、画面のタイムアウト）は `Preferences` ケイパビリティです。コントロールセンターと Settings アプリは同じ値を変更し、システム UI は明るさとタイムアウトをディスプレイに適用して、再起動後も保持します。

アプリ上での右スワイプは戻る操作です。`app.navigation(depth)` でページを報告したアプリは、深さが 0 より大きい間は `app:back` を受け取ります。それ以外の場合は、アプリがバックグラウンドに移り、ランチャーが表示されます。

## システムアプリ

システムアプリは組み込みアプリです。`builtin-app-<name>` プラグインが `app-manager` に依存し、`AppManager::add_builtin` でコンテナを追加します。これができるのはイメージに含まれるプラグインだけなので、インストールしたものがシステムアプリになることはありません。システムアプリは他のアプリと同じライフサイクル（アクティブ、非アクティブ、バックグラウンド、サスペンド、終了中）で動き、登録されたすべての Lua パッケージを宣言なしで `require` できます。インストールしたアプリがシステムアプリの ID を使うことはできず、システムアプリはアンインストールできません。

組み込みアプリは、`settings` のような独自の Lua パッケージを通じてデバイスにアクセスします。そのバックエンドは対応するプラグインにあり、そのプラグインが依存するケイパビリティだけを読み取ります。組み込みアプリのパッケージを要求するマニフェストを持つインストール可能なアプリは無効です。組み込みアプリは、システム UI がどんな目的で自分を開くか（たとえばコントロールセンターの Wi-Fi タイルなら `wifi`）を宣言できるので、システム UI が特定のアプリ名を指定することはありません。システムアプリはシステムフォントで描画し、独自のアトラスを同梱しません。

## インストール可能なアプリ

インストール可能なアプリは、まず Workspace の `/workspace/media/apps/<id>` に提示されるコンテナとして始まります。この時点では起動できません。アプリは App API（[App API](/ja/plugins/app-manager/app-api)）に沿って書かれます。マニフェストには、`app` パッケージのバージョン、必須または任意で使う安定パッケージとその最低バージョン、要求するその他のパッケージ、そしてハードウェアと通信する場合は対象のボードを記述します。システムはアプリをデバイスと照合し、ここで動かせないアプリはその理由を表示し、インストールできません。動かせる場合は、インストール画面に、要求する内容が各パッケージのプラグインが宣言した言葉で並びます。利用者がインストールすると、`app-manager` プラグインがコンテナを非公開の `/media/apps/<id>` にコピーし、以降の実行では、アンビエントのパッケージと指定したパッケージだけを `require` できます。

Workflow や Agent は `app.install` でインストールを要求できますが、インストールを完了できるのは利用者だけです。デバイスのインストール画面か、デバイスのセットアップ用ホットスポットにつないだスマートフォンからポータルの Apps ページで完了します。ディスプレイのないボードでは後者の方法でアプリをインストールします。どちらの場合も、インストールされるのは利用者に表示されたものとまったく同じです。インストールを要求した時点で、提示内容のダイジェストが固定されます。提示されるのが署名付きの `.bapp` パッケージの場合もあり、そこからインストールしたアプリは同じ署名者からの更新だけを受け付けます。アンインストールすると、コンテナとアプリのデータが削除されます。Workspace の提示は、作成者が削除するまで残ります。

## フォント

`system-fonts` プラグインは、システムフォントを自身の `/resources/fonts` に組み込み、`app-manager` の `SystemFonts` で UI キットに渡します。デバイス向けのボードはこのプラグインを有効にし、ディスプレイのないボードはその 2.4 MB を省きます。フォントは、システムのビューとシステムアプリが使うサイズの Noto Sans SC（文字は自身の `charset.txt` に含まれるもの）と、アイコンを描画するサイズのシステムアイコンフォントのグリフです。16 px のレギュラーのスロットは本文用のスロットで、GB 2312 の常用字 3,755 字も含みます。そのため、Agent の回答、お知らせ、会話のタイトルなど、出どころが文字を指定しないテキストはこのスロットで描画されます。あるフォントスロットのアトラスを同梱しないビューはシステムフォントで描画するので、インストール可能なアプリもシステムフォントを使えます。それ以外の文字を表示するアプリは、独自のアトラスを組み込みます。アトラスにない文字を含むテキストは、代替の四角形で表示されます。
