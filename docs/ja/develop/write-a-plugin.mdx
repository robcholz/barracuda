---
title: "プラグインを書く"
description: "コーディング Agent と create-plugin skill を使って、Barracuda に機能を追加します。"
---

Barracuda のあらゆる機能はプラグインなので、ランタイムを拡張するにはプラグインを追加します。作業は自分のコンピューター上のリポジトリで、ふだん使っているコーディング Agent（Claude Code、Cursor、Codex）を使って行います。

## コーディング Agent に頼む

リポジトリには `.agents/skills/create-plugin/SKILL.md` に `create-plugin` skill が含まれています。この skill は [Plugin API](/architecture/plugin-api) の契約を一歩ずつ適用するので、出来上がるプラグインは組み込みのプラグインと同じ形になります。

```txt
> .agents/skills/create-plugin/SKILL.md を読んでから、SHT40 温湿度センサーを
  読み取って Lua に公開するプラグインを作成してください。
```

## skill が行うこと

<Steps>
  <Step title="スコープを決める">
    プラグインが受け持つ機能と、その機能が使う他のプラグインを明確にします。使うプラグインだけが、そのプラグインの `depends-on` になります。
  </Step>
  <Step title="ディレクトリを構成する">
    `plugins/<id>/plugin.toml` と `crates/plugin` を作成し、プロファイルまたはボードでプラグインを有効にして、`cargo plugin sync` を実行します。
  </Step>
  <Step title="構築、登録、起動">
    コンストラクターは `new(&mut PluginContext)` の 1 つだけです。契約は `register` で登録し、自身が所有するタスクは `start` で起動します。
  </Step>
  <Step title="呼び出し側が必要とする契約を追加する">
    他のプラグイン向けの型付きケイパビリティ、Workflow の Action と Event、`vm-<name>` プラグインを通じた Lua パッケージ、`agent-<name>` プラグインを通じた Agent Tool などです。
  </Step>
  <Step title="テストとドキュメント">
    プラグインに絞ったテストを書き、決められた形式で `docs/plugins/<id>.mdx` にページを作成します。
  </Step>
</Steps>

## 結果を確認する

```bash terminal
cargo plugin info <id>     # manifest and dependencies
cargo plugin sync --check  # conventions, and the generated registry is current
```

`cargo plugin sync` は、まずすべてのプラグインが規約（レイアウト、スキーマ、ページの形式、クレートの依存関係）に沿っているかを確認します。ローカルではそのプラグイン自身のテストだけを実行し、テストマトリクス全体は CI に任せてください。
