---
title: "ビルドと実行"
description: "ボードを一度選べば、あとは通常の Cargo コマンドでビルド、書き込み、実行ができます。"
---

ボードは一度選ぶだけで、以降の `cargo build` と `cargo run` はすべてそのボードを使います。デバイス向けのボードでは、`cargo run` がファームウェアをビルドして書き込み、ログをこのターミナルに表示し続けます。

```bash
cargo board select
cargo run
```

ホスト向けのボード（`local-linux`、`local-macos`）では、仮想ペリフェラルマネージャーのループバックアドレスも必要です。`BARRACUDA_VIRTUAL_IO_ADDR=127.0.0.1:7878 cargo run` のように実行します（[Virtual IO](/platforms/virtual-io) を参照）。

最初のコマンドは色付きのボード一覧を開きます。矢印キーで移動し、文字を入力するとあいまい検索でき、Enter で選択します。コマンドはボードのバンドルを検証し、選択内容を Git の管理対象外のローカル状態に記録します。対応する自己記述型のプラットフォームを解決し、静的な selected-Platform と selected-Board-HAL の依存関係ブロックを更新し、ターゲットとランナーの設定をローカルに書き込みます。解決されたプラットフォームは、rustup ツールチェーン、任意の `build-std` ポリシー、インストーラーが生成する環境、そしてツールチェーンがない場合に表示するインストール案内を提供します。選択時にツールチェーンがワークスペースのオーバーライドとして有効になり、その環境が取り込まれます。そのため、通常の `cargo build` と `cargo run` がネイティブの Cargo でスタンドアロンの System アプリケーションを直接扱います。ボードを意識したビルドラッパーやシェルの準備手順はありません。デバイス向けのボードは `--release` でファームウェアをビルドします。System、プラットフォーム、Core、プラグインのログはそのターミナルに表示されます。

外部ターミナルのチャネルは別に実行します。このコマンドは、選択中のボードが組み込みターゲットを使う場合でも、常に開発ホスト向けにコンパイルされます。

```bash
cargo cli
cargo cli configure
```

`cargo cli` は Local/Remote セレクターを開きます。Local は、macOS のランチャーが公開した現在のワークスペースのアドレス、または Linux のエンドポイント `http://10.42.0.2:8787` を表示して使います。Remote はデバイスの IPv4 または IPv6 アドレスを尋ね、ポート 8787 の WebServer に接続します。

`cargo cli configure` も同じ Local/Remote セレクターを使い、その後ターミナル上の設定フォームでモデル、Web 検索、WeChat・QQ・BlueBubbles・Telegram・Inkbox の各チャネルを順に設定します。各プラグインのすべての設定ページは [デバイスポータル](/ja/use/device-portal) にあります。アドレスを明示的に渡すと選択を省略できます。

```bash
cargo cli configure http://DEVICE_ADDRESS:8787
```

ビルド時のプラットフォームのログレベルは、既定で `info` です。1 回のビルドに限って `BARRACUDA_LOG_LEVEL` を設定し、`off`、`error`、`warn`、`info`、`debug`、`trace` から選べます。

```bash
BARRACUDA_LOG_LEVEL=debug cargo run
```

選んだレベルは検証されてプラットフォームのバイナリに組み込まれます。実行時に環境変数から読み込まれることはありません。

自動化の場合は、`cargo board select <board-name>` でプロンプトを省略できます。

プラットフォームやボード HAL を追加するとき、メンテナーは追跡対象のレジストリを一度更新し、生成されたブロックをコミットします。

```bash
cargo platform sync
cargo board sync
```

CI は、対応する `--check` 形式を使えば書き込みなしで検証できます。最新のコミットを pull したときに、追加の同期手順が必要になることはありません。

利用できるボード名は `boards/configs/` 配下のディレクトリ名です。デバイス向けのボードの `toolchain.target` がローカルの Cargo のビルドターゲットになります。ホスト向けのボードでは省略します。

メモリープロファイラーはスループットのベンチマークではなく、実行可能なワークロードです。

```bash
cargo run --profile profiling -p barracuda-agent-profile -- agent-init
```
