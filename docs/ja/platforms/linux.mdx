Linux プラットフォームはデバイス向けプラットフォームと同じ `embassy_net::Stack` を動かし、シミュレートしたレイヤー 3 ドライバーを実際の永続的な Linux TUN に接続します。

TUN、フォワーディング、NAT は起動ごとに一度だけ用意します。

```sh
sudo sh platforms/linux/provision.sh barracuda0
```

以降、アプリケーションは root 権限なしで `barracuda0` を開きます。

```sh
cargo board select local-linux
BARRACUDA_VIRTUAL_IO_ADDR=127.0.0.1:7878 cargo run
```

`BARRACUDA_VIRTUAL_IO_ADDR` は必須です。仮想ペリフェラルマネージャーが待ち受けるループバックアドレスを指定します。`local-linux` は仮想ピン `vio-0` から `vio-7` と、2 つの仮想 I2C コントローラーを公開します。マネージャーは入力レベルの操作、I2C デバイスの接続、障害の注入を行います。詳しくは [`platforms/virtual-io`](/platforms/virtual-io) を参照してください。

このターミナルが System とそのログを受け持ちます。外部ターミナルのチャネルに接続するには、別のターミナルで `cargo cli` を起動してください。

- オペレーティングシステム側のピア: `10.42.0.1/30`
- Embassy Net スタック: `10.42.0.2/30`（デバイスのサービスが待ち受けるアドレス）

プラットフォーム、System、Core、プラグインのログは、`info` レベルで標準エラー出力に書き出されます。ビルドごとに別のレベルを選ぶには、たとえば `BARRACUDA_LOG_LEVEL=debug cargo run` のようにします。
