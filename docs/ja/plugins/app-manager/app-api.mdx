App API は、インストール可能なアプリがデバイスをまたいで頼りにできるものです。使ってよい Lua パッケージ、デバイスに問い合わせてよいこと、そしてその両方を安定させるルールからなります。App API は 2 つの部分に分かれます。このプラグインの `app` パッケージには **API レベル** というバージョンがあります。このシステムはレベル 1 を実装しており、アプリは対象とするレベルをマニフェストの `api` で指定します（[アプリの形式](/ja/plugins/app-manager/app-format) を参照）。それ以外のパッケージは、デバイスが登録しているものがそのまま使え、それぞれが何を約束するかを自ら宣言します。

システムアプリは App API に縛られません。イメージに同梱されており、すべてのパッケージを `require` できます。

## パッケージ

Lua パッケージを登録するプラグインは、何を約束するかを `LuaPackage::interface` で宣言し、インストール画面に表示する説明も宣言します。このプラグインは、それらの宣言を `LuaPackageRegistry` から読み取ります。他のプラグインのパッケージ名を直接指定することはないので、デバイスがアプリに提供するものは、有効なプラグインが登録したものとちょうど一致します。各パッケージの関数と、それぞれがどのバージョンで追加されたかは、パッケージを提供するプラグインのページに記載されています。

| インターフェース | アプリが入手する方法 | どのデバイスでも同じか |
| --- | --- | --- |
| アンビエント | 常に、要求なしで | はい |
| 安定、バージョン付き | マニフェストの `requires` または `uses` に、`name` または `name@version` として記述 | はい（デバイスが持っている場合） |
| ボード固有 | `permissions` と `boards` | いいえ。特定のボードのハードウェアと通信します |
| なし | `permissions` | 約束しません |

ボードのデバイスを必要とするパッケージは、ボードにそのデバイスがない間は何も宣言しません。そのため、そのようなボードでは、そのパッケージを必須とするアプリはインストールされません。

このプラグイン自身のパッケージは次のとおりです。

| パッケージ | インターフェース | Lua API |
| --- | --- | --- |
| `app` | アンビエント、バージョン 1 | アプリ自身: イベント、ビュー、ストレージ、`app.device()`（[アプリの形式](/ja/plugins/app-manager/app-format)） |
| `notify` | 安定、バージョン 2 | `notify.post`、`notify.ask`（後述） |

### `notify`

- `notify.post(title [, body]) -> id` は、通知センターにお知らせを追加します。
- `notify.ask(title [, body [, allow, deny]]) -> allowed` は、どのお知らせよりも前に並ぶカードで相手に尋ね、回答を待ちます。許可されると `true`、拒否または閉じられると `false` を返します。バージョン 2 からは、`allow` と `deny` でカードの 2 つのボタンの名前を指定できます（指定しない場合は「許可」と「拒否」を意味する既定のラベルになり、それぞれ最大 6 文字）。例: `notify.ask("Lights on?", nil, "Now", "Later")`。

失敗した場合は `nil` とメッセージを返します。

## インストール時のチェック

システムは、提示されたアプリをインストールする前に、次の順序でデバイスとの適合をチェックし、最初に見つかった理由で停止します。`app.list` はその理由をアプリの `incompatible` として報告し、インストール画面はそれを表示してインストールボタンを無効にします。`app.install` は `{"error": "incompatible", "reason": …}` を返します。

| チェック | 理由の内容 |
| --- | --- |
| `api` がデバイスのレベルより高い | システムを更新してください。アプリには API 2 が必要ですが、このデバイスは 1 です |
| `boards` にこのボードが含まれていない | espressif-esp-vocat-v1-2 専用です（列挙されたボード） |
| アプリにビューがあり、デバイスにディスプレイがない | このデバイスには画面がありません |
| ディスプレイが `view.size` より小さい | 画面が小さすぎます。アプリには 480×480 が必要です |
| `view.shape` が `rect` で、ディスプレイが円形 | アプリには四角い画面が必要です |
| `requires` のパッケージが、このデバイスで安定パッケージになっていない | このデバイスには notify がありません |
| このデバイスでのバージョンが `requires` で指定したものより低い | システムを更新してください。アプリには notify バージョン 2 が必要ですが、このデバイスはバージョン 1 です |
| `permissions` のパッケージがない | このデバイスは serial に対応していません |

インストール済みのアプリが、ボードやシステムの変更によって適合しなくなった場合は、開けなくなります。`app.open` は `incompatible` を返します。

### ビューとディスプレイ

ビューはスケーリングされず、ディスプレイのサイズでレイアウトされます。ルートがディスプレイ全体を占め、レイアウトは flexbox です。そのため、親を埋め（`w-full`、`h-full`）、両側の余白で列の間隔を取り（`left-[40px] right-[40px]`）、`justify-center` で中央に寄せたビューは、他のサイズのディスプレイにも収まります。固定サイズは書いたとおりのままです。`view.size` は、そのビューが収まる最小のディスプレイを表します。円形のビュー、つまり内接円の中に収まるビューは、長方形のディスプレイにも収まります。`rect` のビューは円形のディスプレイには収まりません。四隅が欠けてしまうためです。テキストのサイズは変わりません。フォントのスロットは固定のピクセルサイズで組み込まれています。ディスプレイのサイズが必要なビューは、`app.device().display` から読み取ります。

## 実行

インストール可能なアプリの実行では、アンビエントのパッケージと、マニフェストの `requires`、`uses`、`permissions` で指定したすべてのパッケージを `require` できます。アプリが指定していないパッケージは存在せず、`require` は失敗します。`uses` のパッケージは、存在しないか、アプリが望むより古い場合があります。`require` する前に `app.device().capabilities` を確認するか、`pcall(require, name)` を呼び出してください。

`app.device()` はデバイスを表し、`capabilities` は各安定パッケージをそのバージョンに対応付けます。

```lua
{
  api = 1,
  board = "espressif-esp-vocat-v1-2",
  display = { width = 360, height = 360, round = true },  -- nil without one
  touch = true,
  capabilities = { notify = 2, ... },
}
```

## バージョン管理

- 安定パッケージのインターフェースは、一度宣言したら変わりません。関数の削除、名前の変更、引数や戻り値の変更は行いません。
- 関数を追加すると、パッケージのバージョンが上がります。各バージョンで何が追加されたかは、そのプラグインが記載します。
- 互換性のない変更は、新しい名前の新しいパッケージになります。古いパッケージは残ります。
- `app` パッケージも同じルールに従い、API レベルをバージョンとします。
- ボード固有のパッケージや何も約束しないパッケージは、システムの更新のたびに変わる可能性があります。そのため、それらを使うアプリは対象のボードを指定します。
