Barracuda は、はしごを上るように体験していきます。段階が上がるごとに求められることは少しずつ増え、得られる自由は大きく広がります。どの段階もそれ自体で役に立つので、プロジェクトに必要な段階より上に進む必要はありません。どの段階でも、大変な作業は Agent が引き受けます。

| 段階 | 名前 | 対象 | やること | 場所 | Agent | 出発点 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | そのまま使う | すべての人 | ブラウザからインストールし、ボードに作業を頼む | ブラウザ、スマートフォン、デバイス | オンボード Agent が VM スクリプトを書いて実行します | [デバイスポータル](/ja/use/device-portal) |
| 2 | 構成 | メイカー、教育者 | ファームウェアに入れるプラグインを選び、ビルドして書き込む | 開発者のマシン | —（生成ではなく設定） | [ボードプロファイル](/ja/boards/profiles) |
| 3 | アプリを作る | アプリ開発者 | アプリを説明し、ロジックと UI を生成して書き込む | Live Editor（ブラウザ） | ブラウザ内の Agent | [デバイス UI](/ja/architecture/device-ui) |
| 4 | プラグインを作る | プラグイン開発者 | ランタイムに新しい機能を追加する | 開発者のマシン | コーディング Agent + `create-plugin` skill | [プラグインを書く](/ja/develop/write-a-plugin) |
| 5 | ボードとプラットフォームを追加する | コントリビューター、ボードベンダー | 新しいボードや新しいチップファミリーに Barracuda を移植する | 開発者のマシン | コーディング Agent + `create-board`、`create-platform` skill | [ボード](/boards/overview) |
| 6 | 完全にカスタマイズする | ビルダー | プラットフォームとボードを選ぶか作成し、プラグインを削るか作成し、ファームウェアをリソース予算に合わせる | 開発者のマシン | コーディング Agent + `fully-customize` skill | [カスタムファームウェア](/ja/develop/custom-firmware) |

## 段階 1: そのまま使う

**ドキュメント:** [デバイスポータル](/ja/use/device-portal) · [チャネル](/ja/use/channels) · [スクリプト](/ja/use/scripts) · [オートメーション](/ja/use/automations)

**目標:** ツールチェーンなしで、数分のうちに会話して行動するデバイスを動かします。

1. Web インストーラーを開き、ボードとバージョンを選び、USB を接続してインストールします。各ボードには、既定のプラグインの組み合わせを持つ既定のファームウェアが用意されています。
2. 同じページから Wi-Fi に接続します。インストーラーからデバイスポータルに引き継がれます。
3. モデルを登録し、チャネル（WeChat、Telegram、QQ、iMessage、Web チャット、ターミナル）を紐付けます。
4. ボードに物理的な操作を頼みます。たとえば「LED を 1 秒に 2 回点滅させて」「画面に温度を表示して」「明るさが下がったら教えて」などです。

オンボード Agent は短い VM スクリプトを書き、すぐに実際のハードウェアに対して実行することで応えます。スクリプト、その出力、結果は会話の中に表示されます。長く続ける動作は Workflow のオートメーションとスケジュールが動かし続けるので、チャットが終わった後もデバイスは働き続けます。

**支える仕組み:** Web インストーラー、デバイスポータル、オンボード Agent、VM とそのペリフェラルパッケージ、チャネル、Workflow。

## 段階 2: 構成

**ドキュメント:** [ボードプロファイル](/ja/boards/profiles) · [ビルドと実行](/ja/get-started/build-and-run) · [CLI](/ja/reference/cli)

**目標:** コードを書かずに、プラグインを選んでデバイスをプロジェクトに合わせます。

プラグインはファームウェアに組み込まれてコンパイルされるので、プラグインの組み合わせは開発者のマシンで選びます。ボードを選び、プロジェクトに必要なプラグイン（カメラ、ディスプレイ、LED ストリップ、センサー、Web 検索、メッセージングのチャネルなど）を選んで残りを外し、ビルドして書き込みます。選び方は 3 つあります。

- 選択肢のプラグインを一覧表示する対話型のコマンド
- 有効なプラグインを列挙する設定ファイル（バージョン管理するプロジェクト向け）
- 開発者のコーディング Agent。要件を伝えるとプラグインを選び、ファームウェアをビルドします

外したプラグインは、メモリーもフラッシュもタスクも消費しません。デバイス上では、各プラグインがデバイスポータルに専用のページを持ち込むので、どの機能も専用の設定画面と一緒に届きます。

**支える仕組み:** プラグインの宣言、ホストでのビルド、プラグインごとのポータルページ。

## 段階 3: アプリを作る

**ドキュメント:** [デバイス UI](/ja/architecture/device-ui) · [アプリの形式](/ja/plugins/app-manager/app-format) · [App API](/ja/plugins/app-manager/app-api) · [PocketJS](/ja/plugins/app-manager/pocketjs)

**目標:** ファームウェアのプロジェクトを用意せずに、独自の UI を持つ本物のデバイスアプリケーションを作ります。

Live Editor で、開発者がアプリを説明します。ブラウザ内の Agent がアプリのロジックとインターフェースを生成し、開発者はプレビューを見ながら視覚的に改良を重ね、同じページから USB 経由でボードに書き込みます。アプリはデバイス上で App Manager プラグインのもとで動きます。App Manager は、ランタイムの他の部分と並んでアプリのインストール、起動、停止、更新を行います。

**支える仕組み:** Live Editor、ブラウザ内の Agent、App Manager プラグイン、アプリランタイム、ブラウザからの書き込み。

## 段階 4: プラグインを作る

**ドキュメント:** [プラグインを書く](/ja/develop/write-a-plugin) · [Plugin API](/architecture/plugin-api) · [すべてのプラグイン](/plugins/overview)

**目標:** どのデバイスでも使える新しい機能を Barracuda に追加します。

開発者はリポジトリをクローンし、コーディング Agent（Claude Code、Cursor、Codex）にプラグインの作成を頼みます。`create-plugin` skill は Agent に Barracuda のアーキテクチャを伝えます。型付きケイパビリティ、Workflow の Action や Event、Agent Tool のどれを公開すべきか、ライフサイクルとタスクの所有がどう機能するか、プラグインが自身をどう文書化するか、どんなテストを書くべきかです。その結果、公式のプラグインと同じ形のプラグインができあがります。

**支える仕組み:** プラグインの契約、`plugin.toml`、Agent にやさしい API の規約、`create-plugin` skill、プラグインごとのドキュメント。

## 段階 5: ボードとプラットフォームを追加する

**ドキュメント:** [ボード](/boards/overview) · [ペリフェラル](/boards/peripherals) · [プラットフォームアーキテクチャ](/architecture/platform-architecture)

**目標:** 新しいハードウェアで Barracuda を動かします。

- サポート済みのチップ上の **新しいボード** は、記述だけで済みます。チップ、ツールチェーンのターゲット、フラッシュのレイアウト、ペリフェラルです。`create-board` skill がその記述とレイアウトを作成し、ボードは Web インストーラーに表示されるようになります。
- **新しいプラットフォーム** は、新しいチップファミリーをもたらします。エグゼキューターのエントリー、ネットワークスタック、ファイルシステム、フラッシュ、HAL アダプターを、プラットフォーム契約の背後に実装します。`create-platform` skill は、System とすべてのプラグインを変えずに、この契約に沿って Agent を導きます。

**支える仕組み:** ボードの YAML とプラットフォーム契約、ボードとプラットフォームの独立した選択、`create-board` と `create-platform` の skill。

## 段階 6: 完全にカスタマイズする

**ドキュメント:** [カスタムファームウェア](/ja/develop/custom-firmware)

**目標:** チップ、リソース予算、用途にぴったり合わせた製品ファームウェアを作ります。

ビルダーがターゲットと要件を伝えます。`fully-customize` skill を使うと、コーディング Agent がプラットフォームとボードを選ぶか作成し、プラグインの組み合わせを選び、予算に対して重すぎるプラグインを削り、足りないものを作成し、結果がデバイスのメモリーとフラッシュに収まることを確認します。出来上がるのは、製品に必要なものだけを含むファームウェアです。

**支える仕組み:** これより下のすべての段階（プラグイン、ボード、プラットフォーム、それらを作成する skill）を、1 つの Agent が 1 つの目標のもとに組み合わせます。

## 段階間の移動

- どの段階も、具体的な成果物を次の段階に引き渡します。オンボード Agent が書いたスクリプトはアプリになり、新しい機能を必要とするアプリはプラグインになり、新しいハードウェアを必要とするプラグインはボードになります。
- 上の段階での作業が下の段階を壊すことはありません。完全にカスタマイズしたファームウェアでも、ブラウザからインストールでき、デバイスポータルがあり、オンボード Agent はスクリプトを書きます。
- ドキュメントは段階ごとに構成されているので、読者は自分のいる段階から始められます。
