Barracuda デバイスにできることは、すべてプラグインから来ています。ランタイム自体は小さく、プラグインを依存関係の順に登録してまとめて起動する、移植可能な System だけです。デバイスのカスタマイズも、その上での開発も、拡張も、結局はプラグインを選ぶ、設定する、削る、書くことに行き着きます。

## プラグインとは

プラグインは、安定した ID と宣言された契約を持つ、自己完結した単位です。

- **ID と依存関係。** `plugin.toml` で、プラグインの ID、依存するプラグイン、ビルドタスクを定義します。
- **型付きケイパビリティ。** プラグインはドメイン API を他のプラグインに提供し、他のプラグインの API を要求できます。プラグイン同士はこれで直接連携します。
- **Workflow の Action と Event。** プラグインは、スキーマで検証される安定した契約を通じて、操作や事実を Workflow のオートメーションに公開できます。
- **Agent Tool。** プラグインは、Agent 向けに設計されたモデル向けのツールを通じて、オンボード Agent に新しい能力を与えられます。
- **VM パッケージ。** プラグインはハードウェアやサービスをスクリプトに公開できるので、オンボード Agent がその場で書くコードから利用できます。
- **ポータルのページ。** プラグインは独自のページ、アイコン、状態をデバイスポータルに追加できるので、どの機能も専用の設定画面と一緒に届きます。
- **リソースとストレージ。** プラグインは自身のファイル、設定、長時間動くタスクを所有し、停止時にそれらを解放します。
- **ドキュメント。** 各プラグインは、ケイパビリティ、ツール、Action、Event、エラー、ライフサイクルを、人と Agent の両方に向けて自身の `docs/plugin.md` に記述します。

## なぜ基本単位なのか

- **追加の方法が 1 つだけ。** センサードライバー、メッセージチャネル、Web 検索プロバイダー、そして Agent 自体もすべてプラグインです。別の拡張の仕組みを覚える必要はありません。
- **組み合わせられる。** プラグインは互いの内部ではなくケイパビリティに依存するので、自由に組み合わせられます。
- **取り外せる。** 有効にしていないプラグインはバンドルされません。プラグインを外せば、そのメモリー、フラッシュ、タスクが解放されます。
- **移植できる。** プラグインは特定のチップではなく移植可能なサービスに依存するので、同じプラグインがすべてのプラットフォームで動きます。
- **Agent にやさしい。** 契約は Agent が読み、使い、書けるほど明示的です。オンボード Agent はプラグインのツールを呼び出し、コーディング Agent は `create-plugin` skill でプラグインを作成します。

## プラグインカタログ

| 分類 | 例 |
| --- | --- |
| デバイス | Wi-Fi のプロビジョニングとセットアップ用ホットスポット、Web サーバー、デバイスポータル、HTTP クライアント、時刻、スケジューラー |
| Agent | オンボード Agent、Web 検索、ファイル、Agent 向け HTTP、スケジュール、Workflow へのアクセス、VM へのアクセス |
| チャネル | WeChat、Telegram、QQ、iMessage、Inkbox、Web チャット、ターミナル |
| オートメーション | Workflow、スケジューラー |
| スクリプティング | VM とそのパッケージ |
| ペリフェラル | GPIO、アナログ、I2C、I2S、SPI、UART、PWM、ディスプレイ、カメラ、オーディオ、IMU、LED ストリップ、電源モニター、ファイルシステム、メッセージキュー、システム情報 |
| アプリ | App Manager とアプリランタイム |

## プラグインによるカスタマイズ

| 誰が | カスタマイズの方法 |
| --- | --- |
| ユーザーとメイカー | 自分のマシンでプラグインの組み合わせを選んでビルドし、各プラグインをデバイスポータルで設定します |
| アプリ開発者 | Live Editor を通じて、アプリからプラグインを利用します |
| プラグイン開発者 | `create-plugin` で新しいプラグインを作成します |
| ビルダー | 製品に必要なプラグインの組み合わせを正確に選び、`fully-customize` で各プラグインをターゲットの予算に合わせて削ります |

## リソースに収める

Barracuda は、RAM が数百キロバイトしかないマイコンでも、外部メモリーを持つボードでも、デスクトップのホストでも動きます。ターゲットに収めるための主な手段は、プラグインの組み合わせです。

- 小さなターゲットには、ネットワーク、ポータル、Agent、VM、チャネル 1 つといった必須のものだけを入れます。
- 大きなターゲットには、ペリフェラル、追加のチャネル、アプリ、並行して動くスクリプトを加えます。
- 製品のファームウェアには、その製品に必要なものだけを入れ、それ以外は入れません。
