Barracuda は AI を 3 つの場所に置きます。それぞれが最も得意な仕事のために選ばれており、どれもプラグインを機能の単位として扱います。

|  | オンボード Agent | ブラウザ内の Agent | 手元のマシンのコーディング Agent |
| --- | --- | --- | --- |
| 動く場所 | デバイス上 | Live Editor の中 | 開発者のマシン上（Claude Code、Cursor、Codex） |
| 動くタイミング | 実行時 | ビルド時 | ビルド時 |
| 役割 | その場のコーディング: ハードウェアをすぐに動かす VM スクリプトを書きます | アプリ開発: デバイスアプリとその UI を生成します | プラグイン、ボード、プラットフォームを作成し、完全にカスタムなファームウェアを組み立てます |
| 重さ | 軽量で、デバイスの制約内で動きます | 重量級で、フルサイズのモデルと十分なコンテキストを使います | 重量級で、リポジトリ全体とツールチェーンを使います |
| 生み出すもの | すぐに実行されるスクリプト | デバイスに書き込まれるアプリ | ファームウェアになるソースコード |
| はしごの段階 | 1 | 3 | 4、5、6 |

## オンボード Agent: その場のコーディング

オンボード Agent は、Agent プラグインとしてデバイス上で動きます。セッション、メモリー、計画、サブ Agent、skill、ツールを自身で持ち、リモート呼び出しになるのはモデルの推論だけです。推論先は、ユーザーが設定したモデルプロバイダーか Barracuda のモデルサービスです。ユーザーは、WeChat、Telegram、QQ、iMessage、デバイスの Web チャット、ターミナルなど、どのチャネルからでも話しかけられます。

最大の特長は **その場のコーディング** です。依頼が物理的な世界に関わるとき、Agent は短い Lua スクリプトを書き、デバイス上の VM で実行します。VM パッケージがハードウェア（GPIO、I2C、SPI、UART、PWM、アナログ入力、ディスプレイ、カメラ、オーディオ、IMU、LED ストリップ、電源モニタリング）を公開しているので、スクリプトは実行した瞬間に実際のペリフェラルを読み取り、操作します。スクリプトは実行中にユーザーへ入力を求めたり、進捗を報告したりでき、一覧表示やキャンセルもできます。スクリプトから Agent に質問することもできるので、実行中のプログラム自身も推論できます。

会話が終わった後も続ける必要がある動作には、Agent は Workflow のオートメーションとスケジュールを使います。たとえば「毎朝 7 時に」「ボタンが押されたら」「温度が 30°C を超えたら」といったものです。

**あえて軽量にしている理由。** デバイスのメモリー予算は決まっており、実行スロットも多くありません。オンボード Agent の仕事はソフトウェアを作ることではなく、デバイスにすでにあるものを使って、素早く、安全に、目に見える形で行動することです。それより大きな仕事はビルド時に回します。

## ブラウザ内の Agent: アプリ開発

ブラウザ内の Agent は Live Editor の中にいます。開発者がアプリを説明すると、Agent がそのロジックと UI を生成し、開発者はライブのビジュアルプレビューで仕上げていきます。準備ができたら、ブラウザが USB 経由でデバイスに書き込みます。

デバイス上では、アプリは App Manager プラグインが管理し、他のすべてのプラグインと並んでアプリランタイムで動きます。アプリはシステムの他の部分と同じ契約を通じてデバイスのプラグインを使うので、ディスプレイ、センサー、ネットワーク、オンボード Agent を利用できます。

**ブラウザを使う理由。** アプリの生成には、大きなモデル、大きなコンテキスト、そして「生成、プレビュー、調整」というビジュアルなループが役立ちます。ブラウザはインストール不要でこの 3 つをすべて提供し、書き込みに使う USB 接続もすでに握っています。

## 手元のマシンのコーディング Agent: プラグイン、ボード、プラットフォーム、ファームウェア

ランタイムのコード（プラグイン、ボード、プラットフォーム、カスタムファームウェア）の作成は、開発者のマシン上の Barracuda リポジトリで、開発者がふだん使っているコーディング Agent（Claude Code、Cursor、Codex）を使って行います。

Barracuda は、これらの Agent 向けに **skill** を同梱しています。skill には Barracuda の作り方が記述されているので、Agent は Barracuda 流のやり方で作業できます。

| skill | Agent がそれを使って行うこと |
| --- | --- |
| `create-plugin` | プラグインを作成または更新します。型付きケイパビリティ、Workflow の Action と Event、Agent Tool のどれを使うかを選び、ライフサイクルとタスクの所有を組み込み、スキーマ、ドキュメント、対象を絞ったテストを書きます |
| `create-board` | 既存のプラットフォーム上にボードを追加します。チップ、ターゲット、フラッシュのレイアウト、ペリフェラルを定義します |
| `create-platform` | System やプラグインを変えずに、プラットフォーム契約の背後で新しいチップファミリーを立ち上げます |
| `fully-customize` | プラットフォームとボードを選ぶか作成し、プラグインを選んで削り、足りないものを作成し、ファームウェアをターゲットのリソースに合わせます |

**手元のマシンを使う理由。** この作業には、ソースツリー全体、ネイティブのツールチェーン、ビルド、テスト、そして多くの場合は机の上のハードウェアが必要です。その環境は開発者のマシンであり、そこで最も力を発揮するのは、開発者がすでに信頼しているコーディング Agent です。

## 3 つの Agent の連携

- **はしごを下る方向:** ビルダーのカスタムファームウェアにはオンボード Agent が含まれます。Live Editor で作ったアプリはオンボード Agent を呼び出せます。手元のマシンで作ったプラグインは、スクリプト、アプリ、デバイスポータルから使えるようになります。
- **はしごを上る方向:** デバイス上でアイデアを確かめたスクリプトは、Live Editor でアプリになります。ランタイムにない機能を必要とするアプリは、プラグインになります。新しいハードウェアを必要とするプラグインは、ボードになります。
- **土台は 1 つの契約:** 3 つの Agent はいずれもプラグインの契約を通じて動きます。デバイス上の Agent Tool、エディターのアプリインターフェース、リポジトリのプラグイン・ボード・プラットフォームの契約です。この共通の契約があるからこそ、作業を Agent 間で受け渡せます。
