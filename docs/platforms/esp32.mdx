Espressif chips run Barracuda on five bare-metal Platforms, one per chip. They
share a flash tool, `espflash`, and a flash layout, an ESP-IDF partition table in
each Board's `partitions.csv`. They differ in Rust target and toolchain: `esp` is
Espressif's Rust toolchain, and RISC-V GCC is Espressif's `riscv32-esp-elf` GCC.

| Chip (Platform) | Rust target | Toolchain | Boards |
| --- | --- | --- | --- |
| ESP32 (`esp32`) | `xtensa-esp32-none-elf` | `esp` 1.98.1.0 | 24 |
| ESP32-S3 (`esp32s3`) | `xtensa-esp32s3-none-elf` | `esp` 1.98.1.0 | 36 |
| ESP32-C3 (`esp32c3`) | `riscv32imc-unknown-none-elf` | Rust 1.98.1, RISC-V GCC | 5 |
| ESP32-C6 (`esp32c6`) | `riscv32imac-unknown-none-elf` | Rust 1.98.1, RISC-V GCC | 5 |
| ESP32-P4 (`esp32p4`) | `riscv32imafc-unknown-none-elf` | `esp` 1.98.1.0, RISC-V GCC | 7 |

## Install the toolchain

Install `espup` once, then the toolchain for your chip. `cargo board select`
prints the same command when the toolchain is missing.

<Tabs>
  <Tab title="ESP32, ESP32-S3">
    ```bash terminal
    cargo install espup
    espup install --toolchain-version 1.98.1.0
    ```
  </Tab>
  <Tab title="ESP32-C3, ESP32-C6">
    ```bash terminal
    rustup toolchain install 1.98.1
    cargo install espup
    espup install --stable-version 1.98.1 --targets esp32c3 --esp-riscv-gcc
    ```

    For ESP32-C6, use `--targets esp32c6`.
  </Tab>
  <Tab title="ESP32-P4">
    ```bash terminal
    cargo install espup
    espup install --toolchain-version 1.98.1.0 --targets esp32s3,esp32p4 --esp-riscv-gcc
    ```

    `espup` installs the `esp` toolchain beside an Xtensa target, so the
    command names `esp32s3` too.
  </Tab>
</Tabs>

`espup` writes `~/export-esp.sh`. Board selection imports it, so you do not
source it yourself. Install `espflash` to flash:

```bash terminal
cargo install espflash
```

<Note>
  The ESP32-S3 Platform stays on `esp` 1.98.1.0: version 1.99.0.0 reorders
  esp-hal's startup code so that release builds no longer link.
</Note>

## Build, flash, and run

```bash terminal
cargo board select m5stack-cores3
cargo run
cargo image deploy
```

- `cargo run` builds the firmware with `--release`, flashes it with
  `espflash flash --monitor`, and keeps the serial log in the terminal.
- `cargo image deploy` builds the Plugin resource image and writes it to the
  `resources` partition with `espflash write-bin`.

A [release](/contributing/releases) ships each ESP Board as `firmware.bin`, the
bootloader, partition table and app merged from `0x0`, beside
`resources.img`. The browser [installer](/get-started/installation) writes
both; to write them yourself, run `espflash write-bin` with each part's offset
from `manifest.json`.

## Hardware the Platforms drive

Every ESP32 Platform provides digital inputs and outputs, GPIO, SPI devices,
SPI buses, SPI outputs, and I2C devices. Runtime I/O lets Lua scripts claim
these controllers on a Board's exposed pins:

| Platform | I2C | SPI | UART | ADC |
| --- | --- | --- | --- | --- |
| `esp32` | `I2C0`, `I2C1` | `SPI2`, `SPI3` | `UART1` | `ADC1` |
| `esp32s3` | `I2C0`, `I2C1` | `SPI2`, `SPI3` | `UART1` | `ADC1` |
| `esp32p4` | `I2C0`, `I2C1` | `SPI2`, `SPI3` | `UART1` | `ADC1` |
| `esp32c3` | `I2C0` | `SPI2` | `UART1` | `ADC1` |
| `esp32c6` | `I2C0` | `SPI2` | `UART1` | `ADC1` |

ESP32-S3 adds quad SPI devices, SD/MMC cards, camera capture, I2S audio
streams, and capacitive touch.
