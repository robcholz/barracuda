STM32 chips run Barracuda on the bare-metal `stm32` Platform. It builds with
standard Rust and flashes through a debug probe with `probe-rs`; the flash
layout is the linker's `memory.x` in each Board's bundle.

| Chip (Platform) | Rust target | Toolchain | Flash tool |
| --- | --- | --- | --- |
| STM32U5A5ZJ (`stm32`) | `thumbv8m.main-none-eabihf` | Rust 1.98.1 | `probe-rs` |

## Install the toolchain

```bash terminal
rustup toolchain install 1.98.1 --target thumbv8m.main-none-eabihf
cargo install probe-rs-tools
```

## Build, flash, and run

Connect the Board's debug probe over USB, then:

```bash terminal
cargo board select nucleo-u5a5zj-q
cargo run
cargo image deploy
```

- `cargo run` builds the firmware and runs it with `probe-rs run`.
- `cargo image deploy` builds the Plugin resource image and writes it with
  `probe-rs download`.

A [release](/contributing/releases) ships STM32 Boards as `firmware.elf` and
`resources.img`, which the browser installer does not write. Write them with
`probe-rs download`: the ELF as it is, and the resource image with
`--binary-format bin --base-address` set to its offset in `manifest.json`.

## Hardware the Platform drives

The `stm32` Platform provides digital inputs and outputs, GPIO, I2C devices,
and SPI buses. Runtime I/O lets Lua scripts claim these controllers on a
Board's exposed pins:

| I2C | SPI | UART | ADC |
| --- | --- | --- | --- |
| `I2C1` | `SPI1` | `USART1` | `ADC1` |
