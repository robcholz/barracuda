The Time Plugin synchronizes UTC time over SNTP, keeps the Board's real-time
clock, and publishes the time as a typed, read-only clock capability.

- Plugin ID: `time`
- Dependencies: none
- Settings: none
- Context resources: `ip_stack`; the Board's primary real-time clock, when it
  has one (`[peripherals.real-time-clock]`, optional)
- Provided capabilities: `UtcClock`
- Required capabilities: none
- Workflow: none
- Agent Tools: none
- Lua packages: none
- Web: none
- Tasks: one cancellable SNTP synchronization loop (`time_sync_task`, pool
  size 1)
- Storage: none

The Time Plugin owns network synchronization and publishes only the typed,
read-only `UtcClock` capability. It does not know about Agent Tools, Workflow
Actions, or JSON transport. `agent-time` is the separate Agent adapter.

## The real-time clock

On a Board with a real-time clock, registration reads it: when it kept time
through power loss and reads no earlier than 2024, `UtcClock` starts from it
(`UtcClockUpdater::seed`), so the time is there at boot instead of only after
the first SNTP answer. Network time always replaces it, and every accepted
SNTP sample is written back to the real-time clock from `time_sync_task`, so
the next boot starts close to network time. `UtcClock::source()` says where
the current time came from (`ClockSource::RealTimeClock` or
`ClockSource::Network`); holdover and staleness apply to either. Without a
real-time clock, the clock reads `Unsynchronized` until SNTP succeeds.
