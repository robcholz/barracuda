Installs the `power_monitor` Lua package over the Board's power monitors,
which the `power` Plugin owns, the primary one by default.

- Plugin ID: `power-monitor`
- Dependencies: `vm`, `power`
- Settings: none
- Context resources: none
- Provided capabilities: none
- Required capabilities: `LuaPackageRegistry` from `vm`, `Power` from `power`
- Workflow: none
- Agent Tools: none
- Lua packages: `power_monitor`
- Web: none
- Tasks: none
- Storage: none

This Plugin installs the `power_monitor` Lua package over `Power`. The
monitors, their drivers, and the battery's charge for other Plugins belong to
the `power` Plugin.

Lua API:

- `power_monitor.list() -> { name, ... }`: the Board names of the monitors,
  the primary one first
- `power_monitor.available([name]) -> boolean`: whether the named monitor, or
  the primary one, exists and can be opened
- `power_monitor.open([name]) -> handle`: opens the named monitor, or the
  primary one
- `handle:measure() -> bus_microvolts, shunt_nanovolts, current_microamps, power_microwatts`
- `handle:battery() -> percent, charging`, or nothing from a monitor that is
  no battery fuel gauge
- `handle:name() -> string`: the monitor's Board name
- `handle:is_open() -> boolean`
- `handle:close()`

The primary monitor is the product's main one, normally the battery's, so a
script that names no monitor reads the battery on every Board. A Board's
other monitors, such as the M5Stack Station's Grove-port monitors
(`port-a1-power` through `port-c2-power`), open by name.

`measure` reads one coherent sample. Bus voltage is positive; shunt voltage,
current, and power are signed, positive in the monitor's IN+ to IN- direction.
A failed measurement returns `nil, error`.

```lua
local power_monitor = require('power_monitor')
for _, name in ipairs(power_monitor.list()) do
  local monitor <close> = assert(power_monitor.open(name))
  local bus_uv, _, current_ua = assert(monitor:measure())
  print(string.format('%s: %.3f V %.1f mA', name, bus_uv / 1e6, current_ua / 1e3))
end
```

Boards without a power monitor still install the package; `list` is empty,
`available` returns false, and `open` returns `nil, error`. One handle may be
opened per monitor and boot; explicit close, lexical `<close>`, collection,
and Plugin revocation prevent further operations on it. While the Board has a
monitor, the package declares a Board-specific interface
(`PackageInterface::BoardSpecific`), because what each monitor measures
depends on the Board's wiring.

A handle reads through the shared `Power`, so other Plugins read the
monitors while a handle is open. The Plugin performs no background sampling
and owns no long-running tasks.
