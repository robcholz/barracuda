Installs the `secure_element` Lua package over the Board's primary secure
element.

- Plugin ID: `secure-element`
- Dependencies: `vm`
- Settings: none
- Context resources: peripheral slot `secure-element.device` (`primary`, optional)
- Provided capabilities: none
- Required capabilities: `LuaPackageRegistry` from `vm`
- Workflow: none
- Agent Tools: none
- Lua packages: `secure_element`
- Web: none
- Tasks: none
- Storage: none

This Plugin takes the Board's primary `SecureElement` capability exactly once
and installs the `secure_element` Lua package. A secure element holds private
keys it never reveals; scripts ask it to sign and to compute public keys, and
read its factory serial number and its random generator.

Lua API:

- `secure_element.available() -> boolean`
- `secure_element.serial_number() -> binary string`, the element's
  factory-unique serial number (nine bytes on an ATECC608)
- `secure_element.random(length) -> binary string` of 1 through 1024 random
  bytes from the element's generator
- `secure_element.public_key(slot) -> binary string`, the P-256 public key of
  the private key in `slot`: X then Y, 32 bytes each, big-endian
- `secure_element.sign(slot, digest) -> binary string`, the P-256 ECDSA
  signature of a 32-byte digest, such as a SHA-256 hash, with the private key
  in `slot`: R then S, 32 bytes each, big-endian

Which slots hold private keys is fixed when the element is provisioned. A
Microchip Trust&GO ATECC608 (TNGTLS), as on the M5Stack Core2 for AWS, holds
its device key in slot 0. A slot without a P-256 private key, a digest that is
not 32 bytes, or a call while another is running returns `nil, error`.

The random bytes come from the element, not from the Board's entropy source,
which this Plugin does not change.

While the Board has the device, the package declares a stable interface
(`PackageInterface::Stable`), version 1. Boards without a secure element
still install the package; `available` returns false and every other call
returns `nil, error`. Plugin revocation prevents every further call.

```lua
local se = require("secure_element")
local digest = string.rep("\0", 32) -- a SHA-256 hash in practice
local signature = se.sign(0, digest)
```
