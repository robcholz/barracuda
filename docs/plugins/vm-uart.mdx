Installs the `uart` Lua package over the Board's exposed I/O pins.

- Plugin ID: `uart`
- Dependencies: `vm`
- Settings: none
- Context resources: `hal.exposed_io`
- Provided capabilities: none
- Required capabilities: `LuaPackageRegistry` from `vm`
- Workflow: none
- Agent Tools: none
- Lua packages: `uart`
- Web: none
- Tasks: none
- Storage: none

This Plugin shares the Board's unified exposed-I/O owner and installs the
`uart` Lua package. A port implements `embedded_io_async::Read + Write`;
controller allocation and pin routing remain inside the Platform provider.

Lua API:

- `uart.available(tx, rx) -> boolean`
- `uart.open(tx, rx, baud, data_bits, parity, stop_bits[, de]) -> handle`
- `handle:read(max_length) -> bytes`
- `handle:write(bytes)`
- `handle:flush()`
- `handle:is_open() -> boolean`
- `handle:close()`

`tx` or `rx` may be `nil`, but not both. Data bits are `7`, `8`, or `9`;
parity is `"none"`, `"even"`, or `"odd"`; stop bits are `1` or `2`.
Opening atomically consumes every selected physical pin from the same owner
used by the other exposed protocols.

For an RS485 transceiver, `de` names the pin that enables its driver (often
labelled DIR or DE/RE). The port then raises it for each write, waits until
the last stop bit has left the UART, and lowers it again, so the transceiver
listens at all other times; `de` needs a `tx` pin. Boards with an RS485 port
expose its three pins, such as `rs485-tx`, `rs485-rx`, and `rs485-dir`:

```lua
local uart = require("uart")
local bus <close> = uart.open("rs485-tx", "rs485-rx", 9600, 8, "none", 1, "rs485-dir")
bus:write("\x01\x03\x00\x00\x00\x01\x84\x0a")
local reply = bus:read(7)
```
