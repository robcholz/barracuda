Installs the `vibration` Lua package over the Board's primary vibration motor.

- Plugin ID: `vibration`
- Dependencies: `vm`
- Settings: none
- Context resources: peripheral slot `vibration.device` (`primary`, optional)
- Provided capabilities: none
- Required capabilities: `LuaPackageRegistry` from `vm`
- Workflow: none
- Agent Tools: none
- Lua packages: `vibration`
- Web: none
- Tasks: none
- Storage: none

This Plugin takes the Board's primary `Vibration` capability exactly once and
installs the `vibration` Lua package. It consumes the semantic peripheral and
never reaches the PMIC or expander that drives the motor.

Lua API:

- `vibration.available() -> boolean`
- `vibration.variable() -> boolean` reports whether the strength is adjustable
- `vibration.set(strength) -> true` runs the motor until changed; 0 stops it
- `vibration.stop() -> true`
- `vibration.pulse(duration_ms[, strength]) -> true` runs the motor once and
  returns when it stops
- `vibration.pattern(steps[, strength]) -> true` runs
  `\{ \{on_ms, off_ms\}, ... \}`, at most 64 steps, and returns when it ends

`strength` is 0 through 100 percent and defaults to 100; a motor without
strength control runs fully for any non-zero strength. A strength above 100
or a call while another is running returns `nil, error`. Cancelling `pulse` or
`pattern` stops the motor.

While the Board has the device, the package declares a stable interface
(`PackageInterface::Stable`), version 1. Boards without a motor still install
the package; `available` returns false and every other call returns
`nil, error`. Plugin revocation prevents every further call.

```lua
local vibration = require("vibration")
vibration.pattern({ { 80, 60 }, { 80, 0 } }, 70)
```
