---
title: "Scripts"
description: "Ask for something physical and the on-board Agent writes a Lua script and runs it on the hardware."
---

When a request touches the physical world, the on-board Agent writes a short Lua
script and runs it in the device's VM with its `vm_run` tool. The script reads
and drives the real peripherals the moment it runs, and its output comes back
into the conversation.

```txt
> Set pin vio-0 high
```

```lua
local gpio = require("gpio")
local pin = gpio.open_output("vio-0", true, "push-pull")
print("vio-0 is high")
```

## What scripts can use

Each Lua package comes from its own Plugin, so a script can use exactly what the
firmware carries.

| Package | Plugin | For |
| --- | --- | --- |
| `gpio` | [`vm-gpio`](/plugins/vm-gpio) | Digital inputs and outputs on the Board's exposed pins |
| `i2c`, `spi`, `uart` | [`vm-i2c`](/plugins/vm-i2c), [`vm-spi`](/plugins/vm-spi), [`vm-uart`](/plugins/vm-uart) | Buses |
| `pwm`, `analog`, `i2s` | [`vm-pwm`](/plugins/vm-pwm), [`vm-analog`](/plugins/vm-analog), [`vm-i2s`](/plugins/vm-i2s) | PWM outputs, analog inputs, and I2S audio streams |
| `display`, `camera`, `audio` | [`vm-display`](/plugins/vm-display), [`vm-camera`](/plugins/vm-camera), [`vm-audio`](/plugins/vm-audio) | Screens, cameras, and sound |
| `motion`, `light`, `power_monitor` | [`vm-imu`](/plugins/vm-imu), [`vm-led-strip`](/plugins/vm-led-strip), [`vm-power-monitor`](/plugins/vm-power-monitor) | Motion sensing, LED strips, and power |
| `environment` | [`vm-environment-sensor`](/plugins/vm-environment-sensor) | Temperature, humidity, air quality, light, and proximity |
| `buzzer`, `vibration`, `infrared` | [`vm-buzzer`](/plugins/vm-buzzer), [`vm-vibration`](/plugins/vm-vibration), [`vm-infrared`](/plugins/vm-infrared) | Tones, vibration, and infrared remote control |
| `eeprom`, `secure_element` | [`vm-eeprom`](/plugins/vm-eeprom), [`vm-secure-element`](/plugins/vm-secure-element) | Data kept across power loss, and signing with keys the hardware keeps |
| `http`, `filesystem`, `message_queue` | [`vm-http`](/plugins/vm-http), [`vm-filesystem`](/plugins/vm-filesystem), [`vm-message-queue`](/plugins/vm-message-queue) | Requests, files, and queues |
| `agent` | [`vm-agent`](/plugins/vm-agent) | Ask the Agent a question from inside a script |
| `time` | [`vm-time`](/plugins/vm-time) | UTC time through `os.time` and `os.date` |

Each package's page lists its Lua API. The [VM](/plugins/vm) page covers the runtime itself.

## Long-running scripts

`vm_run` runs in the Agent's background pool, so the conversation continues
while a script runs.

- A script that calls `io.read()` pauses and asks you for input; your reply is
  fed back to it.
- The Agent lists, answers, and cancels running scripts with its
  `background_list`, `background_input`, and `background_cancel` tools. Ask it
  to stop a script and it cancels the run.

For behavior that must outlive the conversation, such as "every morning at
seven", the Agent uses [Automations](/use/automations).
