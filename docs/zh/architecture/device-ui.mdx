Barracuda 的设备 UI 由三层构成：**System<strong>、</strong>系统应用**和**可安装应用**。每个界面、手势和应用都恰好属于其中一层，而所属的层决定了谁拥有它、它能做什么，以及它出错时会发生什么。本文是这种划分的权威说明；每个界面的设计见设备 UI 设计文档，各项契约见相应插件的文档。

| | System | 系统应用 | 可安装应用 |
| --- | --- | --- | --- |
| 是什么 | `app-manager` 插件中的原生 Rust 代码 | 内置应用：由另一个插件附带的应用容器 | 放进 Workspace 的应用容器 |
| 存放位置 | `app-manager` 插件的 `/resources/view` | 所属 `builtin-app-<name>` 插件的 `/resources/app` | `/workspace/media/apps/<id>.bapp/` |
| 运行方式 | `app-manager` 任务 | 带 MicroTS 视图的 Lua 运行，受应用生命周期管理 | 同上 |
| Lua 包 | 无 | 所有已注册的 Lua 包，包括它自己的 | 环境 Lua 包及其清单中列出的 Lua 包；永远不能使用内置应用的 Lua 包 |
| 可否移除 | 否 | 否；只能查看应用信息；开发板可以不启用它的插件 | 是；可查看应用信息和卸载 |
| 出错时 | 设备不可用 | System 显示它已退出 | 同上 |
| 示例 | 主屏幕和 Agent 状态、启动器、切换器、通知中心和控制中心、启动中、已退出、应用菜单和应用信息 | Sessions、Workflows、Files、Settings | 空气质量、灯带、摄像头和计数器示例 |

## 相关插件

| 插件 | 包含 |
| --- | --- |
| `app-manager` | 应用套件（应用、生命周期、`app` Lua 包）、UI 套件（视图、显示屏、触摸、手势、系统字体和图标），以及连接两者并运行 System UI 的入口 |
| `builtin-app-<name>` | 一个系统应用：它的容器，以及它自己的 Lua 包的后端 |
| `system-fonts` | 显示屏上所有视图绘制时使用的系统字体 |
| `system-wifi` | System UI 中的 Wi-Fi：连接、离线卡片，以及门户磁贴打开的设置热点，通过 `app-manager` 的 `SystemNetwork` 实现 |

应用套件不需要显示屏。在没有显示屏的开发板上，`app-manager` 插件不运行 UI 套件，也不运行 System UI：它只是无头应用的应用管理器，带视图的应用会返回 `no_display`。System UI 同样不需要网络：只有当某个插件通过 `SystemNetwork` 展示网络时（比如 `system-wifi`），它才会显示网络。带屏幕的开发板指定 `screen` profile（配置档）；从不联网的产品（没有 Wi-Fi、门户、Agent、Sessions 或 Settings）则指定 `screen-offline`。两者都包含 `ui` 层：`app-manager`、`system-fonts`，以及不需要网络的内置应用。各个 profile 见[开发板 profile](/zh/boards/profiles)。开发板不启用某个系统应用的插件，就能把它排除在外；没有显示屏的开发板既不启用系统应用，也不启用 `system-fonts`。

## 确定所属的层

只要满足以下任一条件，就把功能放在 **System** 中：

- 应用卡死或崩溃时，或者没有任何应用运行时，它也必须能工作；
- 它在应用之间做仲裁：显示屏上显示什么、哪个应用在前台、哪些应用在运行；
- 它授予信任：安装、卸载，以及应用可以使用什么；
- 它响应在任何地方都有效的输入：边缘滑动、返回、在系统界面上长按，以及开发板的主页键和 Agent 键。

如果它是设备自带的全屏体验，需要可安装应用不经请求就拿不到的设备状态，并且出错时不会拖垮整台设备，就把它做成**系统应用**：Settings、会话、Workflow、文件。

其他一切都是**可安装应用**：Workspace 中的一个目录，由门户、Agent 或其他插件写入。

## System

`app-manager` 插件的 System UI 就是 System。它是唯一能替用户切换和卸载应用的调用方，也是系统手势的唯一所有者。它的视图位于系统层，在应用层之上：当某个应用在前台且没有系统界面遮挡时，显示该应用的视图；任何系统界面都会遮住应用并停止它的输入（`AppManager::set_interactive`），直到该界面关闭。

UI 套件把触摸转换为点按（作用于显示屏上的视图），以及长按和滑动（只交给 System，`UiService::next_gesture`）。应用永远看不到系统手势，所以任何应用都无法挡住用户的退出路径。视图唯一能得到的手势，是从它可滚动的内容（`overflow-y-auto`）上开始的竖直拖动：它滚动视图，而不算滑动。从顶边往下、从底边往上的拖动始终属于 System，在没有可滚动内容的地方拖动也是。

通知通过 System 的通知中心送达用户。任何插件都可以用 `Notifications` capability 发布通知，Workflow 则用 `app.notify`。需要用户回答的问题（`Notifications::ask`、`app.confirm`）会排在最前面，并在得到回答前一直显示在主屏幕上。主屏幕还会根据 `AgentStatus` 或 `app.agent` 显示 Agent 的状态（待机、聆听、思考、回答）。应用永远不会绘制在其他应用或 System 之上。

设备设置（亮度、音量、静音、麦克风、勿扰，以及屏幕超时）属于 `Preferences` capability：控制中心和 Settings 应用修改的是同一组值，System UI 把亮度和超时应用到显示屏上，并在重启后保留它们。

在应用上向右滑动表示返回：通过 `app.navigation(depth)` 报告了页面层级的应用，在深度大于零时会收到 `app:back`；否则应用会进入后台并显示启动器。

## 系统应用

系统应用是内置应用：一个 `builtin-app-<name>` 插件依赖 `app-manager`，并用 `AppManager::add_builtin` 添加自己的容器。只有镜像中的插件才能这样做，所以任何安装的东西都无法成为系统应用。系统应用与其他应用遵循相同的生命周期（active、inactive、background、suspended、terminating），并且无需声明就可以 `require` 任何已注册的 Lua 包。可安装应用不能占用系统应用的 ID，系统应用也不能被卸载。

内置应用通过自己的 Lua 包访问设备，比如 `settings`，其后端位于它的插件中，只读取该插件所依赖的 capability。清单中请求内置应用 Lua 包的可安装应用是无效的。内置应用可以声明 System UI 在什么情况下打开它，例如控制中心 Wi-Fi 磁贴对应的 `wifi`，这样 System UI 就永远不需要写出某个应用的名字。系统应用使用系统字体绘制，不附带自己的字体图集。

## 可安装应用

可安装应用是 Workspace 中的一个容器目录：`/workspace/media/apps/<id>.bapp/`。把目录放到这里就算安装了，应用也直接从这里运行：不复制、不确认、不签名。能写 Workspace 的都能安装应用，比如门户的文件管理器、Agent 或其他插件；正在写入的应用放在以 `.` 开头的目录里，写完后再改名。

它基于应用 API 编写（[应用 API](/zh/plugins/app-manager/app-api)）：它的清单列出 `app` Lua 包的版本、它依赖或使用的稳定 Lua 包及所需的最低版本、它请求的其他 Lua 包，以及当它直接操作硬件时适用的开发板。System 会根据设备检查它；无法在本机运行的应用在启动器中变暗显示，它的应用信息界面会说明原因。应用的每次运行都只能 `require` 环境 Lua 包和它清单中列出的 Lua 包；应用信息界面会用每个 Lua 包所属插件声明的措辞列出它们。卸载会删除这个目录和应用的数据。

## 字体

`system-fonts` 插件把系统字体烘焙到它的 `/resources/fonts` 中，并通过 `app-manager` 的 `SystemFonts` 交给 UI 套件；设备开发板会启用它，没有显示屏的开发板则省下这 2.4 MB。这些字体是 System 视图和系统应用所用字号的 Noto Sans SC，包含其 `charset.txt` 中列出的字符，以及系统图标字体在各绘制尺寸下的字形。16 px 常规字号是正文字号：它还包含 GB 2312 的 3,755 个常用字，所以没有任何来源指定字体的文本（比如 Agent 的回答、通知或会话标题）都用它绘制。没有为某个字号附带图集的视图会使用对应的系统字体绘制，所以可安装应用也可以使用系统字体；需要显示其他字符的应用要自己烘焙图集。超出图集范围的字符会显示为占位方框。
