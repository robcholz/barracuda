title: "芯片驱动"
description: "编写可复用的底层芯片驱动，供语义外设实现在其上构建。"
---

## 用途

`drivers/chips` 包含面向物理芯片的、可复用的底层寄存器和协议驱动。芯片驱动以芯片自己的术语暴露操作，并使用上游的总线和 GPIO trait。它不决定这颗芯片对 Barracuda 应用意味着什么。

芯片驱动是私有的构建模块。它们不出现在 `board.yml` 中，不拥有 `peripheral.yml`，也不会被 `cargo board` 发现。语义外设实现通过普通的 Cargo 依赖选用它们。

厂商寄存器表以及对其进行规范化的构建期解析器也属于芯片驱动。共享的解析器代码可以放在 `drivers/build-support` 中；它只在构建芯片 crate 时运行，永远不会成为运行时依赖。

## 依赖边界

芯片驱动可以依赖 `embedded-hal`、`embedded-hal-async` 或某个专注的上游协议 crate。它不得依赖：

- `peripherals/api` 或 `peripherals/config`；
- 开发板、Target、System 或插件 crate；
- 厂商 HAL；
- 生成的开发板接线或具体的开发板名称。

使用方提供地址、引脚、延时和总线值。驱动校验芯片层面的输入，并报告芯片错误或传输错误，而不臆造应用语义。

## 组合

一个语义实现可以组合多个芯片驱动。反过来，同一个芯片驱动也可以支持多个语义实现。例如，Tab5 的外设实现各自独立地借用共享的 I2C 资源，并使用 PI4IOE5V6408 驱动来控制它们各自拥有的复位或使能信号。这个扩展芯片本身永远不会成为 System 可见的外设。

即使底层代码很少，这种分离也是有意为之：它让寄存器行为可以复用，并防止辅助芯片泄漏到开发板的语义 API 中。

MIPI-DSI 面板驱动暴露控制器原生的命令序列。显示外设实现选择面板和时序，然后通过平台狭窄的 DSI 命令通道转发这些命令。平台和语义显示 API 都不拥有厂商寄存器表。
