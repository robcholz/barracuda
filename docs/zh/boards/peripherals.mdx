## 概览

Barracuda 把语义外设 API、外设实现和底层芯片驱动分开。开发板恰好有两个公开的硬件面：`peripherals` 和 `exposed-io`。所有只用于构造外设的东西，包括 GPIO 扩展芯片和总线开关，都是其实现私有的。

组合发生在构建时。所选的开发板 HAL 包含具体类型和 `Option<T>` 字段；固件不在运行时查找目录，也不使用外设 trait 对象。

## 所有权边界

- `peripherals/api` 定义与芯片无关的语义契约，例如 `Display`、`Touch`、`PowerMonitor` 和 `RealTimeClock`，以及通用的 `PeripheralImplementation` 构造 trait。
- `peripherals/impl/<peripheral>/<implementation-id>` 把一种具体的硬件配置适配到一个语义 API。它拥有自己的 `peripheral.yml`、初始化策略和私有的辅助芯片依赖。
- `peripherals/config` 只发现外设实现，校验它们的清单和开发板接线，并生成静态的开发板组合。
- `drivers/chips/<chip>` 包含底层的寄存器和协议驱动。芯片驱动既不知道开发板名称，也不知道语义外设 API，并且没有 `peripheral.yml`。
- `boards/hal` 拥有 `BoardResources { peripherals, exposed_io }` 外壳，以及生成的组合所使用的资源适配器。

依赖方向是单向的：

~~~text
Platform HAL resource -> chip driver -> peripheral implementation -> peripheral API
                                  Board wiring -----------^
~~~

当上游生态的 crate 已经提供底层驱动时，外设实现可以不使用单独的芯片 crate。语义边界仍然不变：System 只接收外设 API。

## 开发板模型

`board.yml` 描述的是产品接线，而不是 Rust 模块：

~~~yaml
peripherals:
  io:
    i2c-device:
      internal:
        peripheral: I2C0
        scl: GPIO32
        sda: GPIO31
        frequency-hz: 400000
  devices:
    battery-monitor:
      implementation: ina226-power-monitor
      bindings:
        i2c: internal
      parameters:
        address: 65

exposed-io:
  pins:
    port-a-sda: { pin: GPIO53 }
~~~

`peripherals.io` 声明构造期间使用的私有资源。`peripherals.devices` 选择语义实现。`exposed-io` 是开发板唯一可在运行时配置的 I/O 面。一个芯片原生令牌不能既是私有的外设接线，又是暴露 I/O。

有些面板在主机写入的同一根数据线上应答读取。这样的 `spi-device` 把这根线写作 `mosi`，并设置 `three-wire: true`；它的读取随后从 `mosi` 返回。如果设备只能在比写入更慢的时钟下应答，用 `read-frequency-hz` 指定读取时钟：

~~~yaml
spi-device:
  display-spi:
    peripheral: SPI3
    sck: GPIO17
    mosi: GPIO21
    three-wire: true
    read-frequency-hz: 8000000
    chip-select: GPIO15
    frequency-hz: 40000000
~~~

实现有时驱动、有时读取的线是 `gpio` 绑定：开发板给出它的引脚，实现得到一个 `ConfigurableDigitalPin`，并在输出和输入之间切换它。Tab5 的显示实现在触摸控制器退出复位时把触摸中断线驱动为高电平，以此设定 GT911 的地址，然后把这根线交还给控制器。由实现设置偏置的输入同样是 `gpio` 绑定：`gpio-buttons` 把每个按键引脚设为输入，并使用开发板指定的上下拉。开发板没有给出的可选 `gpio` 或 `digital-input` 绑定以 `None` 交给实现。

接在八位 Intel 8080 总线上的面板是一个 `parallel-output`：写选通线、数据/命令线和片选线，按位序排列的八根数据线，选通时钟，以及 DMA 暂存缓冲区，其大小就是一次片选有效期间发出的最长突发。平台把它作为 `ParallelOutput` 交给显示实现：

~~~yaml
parallel-output:
  display-bus:
    peripheral: LCD_CAM
    dma: DMA_CH1
    wr: GPIO11
    dc: GPIO12
    chip-select: GPIO14
    data: [GPIO13, GPIO9, GPIO8, GPIO7, GPIO6, GPIO5, GPIO4, GPIO3]
    frequency-hz: 10000000
    dma-buffer-bytes: 4096
~~~

直接驱动的电子墨水屏源极驱动器使用同一种绑定，但不带 `dc`：每个字节都是数据，源极时钟接 `wr`，源极起始脉冲接 `chip-select`。它的显示实现把栅极和锁存线作为普通数字输出驱动，并让每一行都在一次突发之内发出。

microSD 卡是一个 `sdmmc-device`：SD 主机、卡所接的主机 `slot`（省略时为 0）、按顺序排列的时钟、命令和数据引脚、`bus-width`（1 或 4）、卡识别后运行的时钟（`frequency-hz`，省略时为 25 MHz），以及芯片用片上稳压器为该槽位引脚供电时，该稳压器的 `power-channel` 和 `power-millivolts`。每个平台列出它交给开发板的 SD 主机槽位及各自需要的供电（`platform.yml` 中的 `hal.sdmmc-slots`），`cargo board select` 会拒绝位于其他槽位、声明其他供电，或位于 Wi-Fi 协处理器所用槽位上的存储卡。ESP32-P4 的存储卡：

~~~yaml
sdmmc-device:
  micro-sd:
    peripheral: SDHOST
    slot: 0
    clk: GPIO43
    cmd: GPIO44
    data: [GPIO39, GPIO40, GPIO41, GPIO42]
    bus-width: 4
    power-channel: 4
    power-millivolts: 3300
    frequency-hz: 40000000
~~~

这个绑定由平台构建。在 ESP32-S3 上，开发板组合取得 SD 主机并构建卡的槽位。在 ESP32-P4 上，由于 Wi-Fi 协处理器的链路使用另一个槽位，SD 主机归平台所有：平台入口只构建一次主机，把槽位 0 与芯片外设一起交给开发板组合，存储卡实现收到的就是这个槽位。

当多个设备共用一条总线（例如 LCD 和 microSD 卡）时，多个 `spi-device` 声明可以使用同一个 SPI 控制器。它们写明相同的 `sck`、`mosi` 和 `miso`，以及各自的 `chip-select` 和 `frequency-hz`；组合只构建一次总线，并交给每个实现一个会选中自身、应用自己时钟的设备。M5Stack Core2 的显示屏和存储卡：

~~~yaml
spi-device:
  display-spi:
    peripheral: SPI3
    sck: GPIO18
    mosi: GPIO23
    miso: GPIO38
    chip-select: GPIO5
    frequency-hz: 40000000
  card-spi:
    peripheral: SPI3
    sck: GPIO18
    mosi: GPIO23
    miso: GPIO38
    chip-select: GPIO4
    frequency-hz: 20000000
~~~

SPI 上的 microSD 卡（`spi-sd-fat-removable-storage`）还会修改其设备的时钟，并在释放片选的情况下输出时钟，这是 SD 规范在识别存储卡时的要求；平台的 SPI 设备类型通过 `SpiDeviceControl` 提供这些操作。

`spi-output` 是由 SPI 控制器输出的 LED 灯带数据线，它独占一个任何 `spi-device` 都没有使用的控制器。因此，除了 `spi-device` 使用的总线之外，开发板还需要为每个 `spi-output` 留出一个空闲的控制器。

`rmt-output` 是遥控收发器（ESP RMT）的一个发送通道及其引脚，`rmt-input` 是一个接收通道。多个通道可以使用同一个收发器：组合只构建一次收发器，并把各自的通道以 `PulseOutput` 或 `PulseInput` 交给每个实现，它们自行输出或记录电平与时长组成的符号。因此，接在 `rmt-output` 上的 LED 灯带（`rmt-led-strip`）不占用 SPI 控制器，红外 LED 和接收器也使用这些通道的载波和毛刺滤波。每个平台列出可以发送和接收的通道（`platform.yml` 中的 `hal.rmt-channels`），`cargo board select` 会拒绝范围之外的通道。M5Stack StickS3 的红外发射器和接收器：

~~~yaml
rmt-output:
  ir-transmit:
    peripheral: RMT
    channel: 0
    pin: GPIO46
rmt-input:
  ir-receive:
    peripheral: RMT
    channel: 4
    pin: GPIO42
~~~

`pwm-output` 是 PWM 控制器（ESP LEDC）的一个定时器、一个输出通道以及它们驱动的引脚。实现通过 `PwmFrequencyControl` 重新设置定时器频率，让无源蜂鸣器改变音高；占空比决定音量。控制器只构建一次并共享：开发板的 PWM 输出和运行时 PWM 池各自使用自己的定时器和通道，`cargo board select` 会拒绝使用池中定时器或通道的输出。M5Stack Dial 的蜂鸣器：

~~~yaml
pwm-output:
  buzzer-tone:
    peripheral: LEDC
    timer: Timer1
    channel: Channel1
    pin: GPIO3
~~~

`analog-input` 是一个 ADC 通道：控制器和引脚。多个输入可以使用同一个控制器；组合会启用每个通道、只构建一次转换器，并把各自的通道交给每个实现，通道读取校准后的毫伏值（`AnalogVoltageInput`）。ESP32-S3-Korvo-2 的按键阶梯和电池：

~~~yaml
analog-input:
  button-ladder:
    peripheral: ADC1
    pin: GPIO5
  battery-sense:
    peripheral: ADC1
    pin: GPIO6
~~~

`pulse-counter` 是解码正交编码器的一个脉冲计数单元：控制器以及 A、B 两路信号的引脚，平台为这两个引脚启用内部上拉。该单元计数两路信号的每个边沿，B 领先 A 时递增，平台在软件中扩展其 16 位计数；实现收到一个 `QuadratureDecoder`。M5Stack Dial 的旋钮：

~~~yaml
pulse-counter:
  knob:
    peripheral: PCNT
    a: GPIO41
    b: GPIO40
~~~

`pdm-i2s-stream` 是同一个 I2S 控制器上的 PDM 麦克风和 I2S 功放，每次只工作在一个方向：`clk` 是麦克风的时钟，同时也是功放的字选择，`din` 是麦克风的数据，`bclk` 和 `dout` 是功放的线路。只有其中一种器件的产品省略另一种的线路。数据流以 `sample-rate-hz` 传输单声道 16 位 PCM；平台按 `dma-buffer-bytes` 分配 DMA 缓冲区。M5Stack Atom Echo：

~~~yaml
pdm-i2s-stream:
  audio:
    peripheral: I2S0
    dma: DMA_I2S0
    clk: GPIO33
    din: GPIO23
    bclk: GPIO19
    dout: GPIO22
    sample-rate-hz: 16000
    dma-buffer-bytes: 4096
~~~

除显示屏外，开发板的每种外设只有一个设备。产品上同一类型有多颗芯片时，由一个组合这些芯片驱动的实现来呈现：M5Stack AirQ 的 SEN55 颗粒物传感器和 SCD40 CO2 传感器是一个 `environment-sensor` 设备，即 `scd4x-sen5x-environment-sensor`，它的测量量是两颗芯片的并集。

每个生成的语义槽位都是可选的。没有实时时钟的开发板就没有 `RealTimeClock` 值；有实时时钟的开发板则有 `Some(concrete_clock)`。缺席不需要伪造硬件，存在也不会暴露辅助芯片。

## 实现清单

每个可选的实现都拥有 `peripherals/impl/<peripheral>/<implementation-id>/peripheral.yml`。父目录等于 `peripheral`，叶目录等于 `id`。版本 1 的清单声明：

- 稳定的实现 ID 和语义外设 API；
- 只供代码生成使用的 Cargo 和 Rust 构造模板；
- 具名的硬件绑定角色和安全的输出初始化策略；
- 类型化的参数、默认值、枚举取值范围和 Rust 值映射。

`peripherals/config::PERIPHERAL_APIS` 是注册边界。未知的语义种类会被拒绝，并提示在它的第一个实现之前先添加它的 API trait。生成器理解绑定类别和所有权，但不包含针对具体实现 ID 的匹配。

`cargo board sync` 校验每个清单并维护工作区依赖。`cargo board select <board>` 根据这些 schema 解析所选的开发板，检查平台 HAL 的支持情况，并只把所选实现的依赖写入 `boards/selected/Cargo.toml`。

## 私有辅助芯片

辅助芯片是实现细节，除非它独立地提供一个 System 使用的语义外设。因此，用于复位、使能、中断或电源控制信号的 I/O 扩展芯片不会自动成为开发板外设。

在 M5Stack Tab5 上，位于 `0x43` 的 PI4IOE5V6408 就是这样被隐藏的：

- 音频编解码器实现拥有扬声器功放的使能引脚；
- 显示实现拥有面板和触摸复位引脚：它根据应答的触摸控制器识别面板，所以和 M5GFX 一样由它让两者退出复位；
- 摄像头实现拥有传感器复位引脚。

这三个实现都使用 `drivers/chips/pi4ioe5v6408`；没有一个向 System 暴露这个扩展芯片、它的引脚或一个通用的系统控制器外设。其他由 PI4 控制的信号同样必须由它们所使能的具体语义服务拥有。

在 M5Stack CoreP4X 上，`corep4x-dsi-display` 以同样的方式隐藏位于 `0x4F` 的 M5IOE1 扩展芯片（面板电源、复位和 PWM 背光）和位于 `0x6E` 的 M5PM1 电源控制器（5 V 升压），分别通过 `drivers/chips/m5ioe1` 和 `drivers/chips/m5pm1`。Paper Mono 的 `paper-mono-display` 用同样两个驱动控制面板电源、复位和前光；`paper-color-display` 和 `paper-diy-display` 用 M5PM1 控制电子墨水屏电源。

如果辅助芯片同时提供一个语义外设，就按寄存器共享，绝不让两个所有者拥有同一个寄存器。在 Core2、Tough、Station、StickC 和 CoreS3 上，`m5stack-pmic-display` 控制 AXP192 或 AXP2101 的稳压器，而 `axp192-axp2101-power-monitor` 通过自己的总线视图读取同一个 PMIC 的电池数据，只访问状态、ADC 和电量计寄存器。`axp192-axp2101-vibration` 在它们旁边只写 Core2 振动马达稳压器的电压字段和使能位，`m5ioe1-vibration` 只写 StopWatch 上 M5IOE1 的 PWM 通道及其引脚。`m5pm1-power-monitor` 和 `pi4ioe5v6408-buttons` 同样只配置自己的 M5PM1 或扩展芯片引脚，其他引脚仍归使用它们的显示实现。

M5Stack PowerHub 的 STM32G031 电源协处理器转发四个语义外设，因此四个实现以同样方式共享它：`powerhub-buttons` 只读取它的按键寄存器，`powerhub-led-strip` 只写 LED 电源、颜色和亮度寄存器，`powerhub-power-monitor` 只写计量使能并读取电池寄存器，`powerhub-rtc` 只访问时钟寄存器。四者都使用 `drivers/chips/m5powerhub`。

## 稳定的构造和运行时行为

`PeripheralImplementation` 声明只能移动（move-only）的 `Bindings`、经过校验的 `Config`、返回的语义 `Peripheral`，以及它的初始化 `Error`。它的 future 不装箱，并且是单态化的。

平台 HAL 模块把厂商令牌转换为 `embedded-hal`、`embedded-hal-async`，或者狭窄的数据面契约，例如 DSI、MIPI-CSI、摄像头采集和 PCM。外设实现依赖这些契约，而不依赖厂商 HAL。芯片驱动通常只依赖上游的协议 trait。

对于 DSI 显示屏，平台绑定建立链路并发送原始 DBI 命令，芯片驱动拥有控制器命令序列，显示实现选择时序并施加所需的延时。这让控制器寄存器既不出现在语义 API 中，也不出现在平台 HAL 中。

生成的代码直接构造每个所选实现，并把它的语义结果存放在 `GeneratedPeripherals` 中。System 和插件使用这些语义值，从不根据原始引脚重新构造实现。

## 添加硬件

添加一块复用现有实现的开发板，通常只需要 `board.yml` 接线和原生布局文件。在现有语义外设背后添加一颗新芯片时，按需添加一个芯片驱动、一个外设实现及其清单。添加一个真正全新的语义外设，则从它的 API trait 和可选的所有权槽位开始，然后再添加实现。

这让开发板数量不会成倍增加 Rust 代码：可复用的芯片行为、语义适配、平台资源构造和产品接线各自位于一层。
