官网、它的安装页、Live Editor 和设备门户共用 `ui/` 里的一套
design system。在这里改一个 token、一个组件或一个图标，四处都会跟着变；它们都不再保留副本。

```bash terminal
bun test ./ui
```

## 里面有什么

| 文件 | 内容 | 谁在用 |
| --- | --- | --- |
| `tokens.css` | 颜色、字体、间距、圆角和尺寸 token，浅色和深色 | 四处都用，文档 `style.css` 里的 token 块也由它生成 |
| `components.css` | 组件，即基于 token 的纯 CSS 类（`bc-*`） | 四处都用 |
| `icons.ts` | Lucide 图标，以 SVG 标记的 `ICON_*` 常量提供 | 四处都用 |
| `marks.ts` | Barracuda 标志：`MARK_ART`、`MARK_BARE` 和 `MARK_TILE` | 四处都用 |
| `dom.ts` | `h`、`append`、`fill`、`svg`、`icon` 和 `mark`：不用框架构建元素 | Live Editor，设备门户的外壳、UI kit 和页面 |
| `prune.ts` | 把 token 和组件裁剪到页面实际用到的部分 | 设备门户的构建 |

## 各个应用怎么用它

| 应用 | 方式 |
| --- | --- |
| 官网和安装页（`website/`） | `src/components/Document.tsx` 引入两份样式表；`Icon` 和 `BrandMark` 取自 `icons.ts` 和 `marks.ts` |
| Live Editor（`apps/live-editor/web/`） | `src/app.css` 引入两份样式表，`build.ts` 把它们打包成一个 `app.css`；`src/ui/icons.ts` 列出它用到的图标 |
| 设备门户（`plugins/captive-portal/`） | `src/app.css` 引入两份样式表，`resources/web/build.ts` 对它们做裁剪；UI kit 把 `dom.ts`、`icons.ts` 和 `marks.ts` 再导出给插件页面 |

## 设备门户的裁剪

设备门户的样式表从设备闪存提供，它的外壳（`index.html`、`app.js` 和 `app.css`）必须小于 96 KiB。构建时会扫描外壳、UI kit 和每个插件的 `resources/web/`，找出用到的 `bc-*` 类，只保留这些规则、它们读取的 token 和它们引用的 keyframes。以短横线结尾的类名（如 `` `bc-badge--${tone}` ``）会保留所有以它开头的类。

页面打开时自己添加的样式表，从 `style.ts` 导出；外壳会去掉这份样式表已经设置的每条声明。所以新增组件在有页面用到它之前，不会让设备门户变大。

## 修改

<Steps>
  <Step title="修改 ui/">
    遵守 `components.css` 开头的规则：按表面选圆角，每种可按状态都要有，选中用安静的填充，焦点只有一条线。新图标以 Lucide 的 `ICON_*` 常量添加。
  </Step>
  <Step title="重新生成生成的文件">
    改了 token 之后，重新生成文档的 token 块：

    ```bash terminal
    bun tools/web/docs-tokens.ts
    ```

    改动涉及设备门户或插件页面时，重新构建它们提交的资源：

    ```bash terminal
    cargo plugin run build
    ```
  </Step>
  <Step title="检查">
    ```bash terminal
    bun run format && bun run lint && bun run check
    bun test ./ui ./tools/web ./plugins/captive-portal
    ```
  </Step>
</Steps>
