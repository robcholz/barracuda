---
title: "发布"
description: "推送版本 tag，为每块设备开发板发布固件。"
---

推送一个版本 tag，GitHub Actions 会按这个版本构建每块设备开发板，然后把固件发布为该 tag 的 GitHub Release。浏览器[安装页](/zh/get-started/installation)提供最新的版本。

```bash terminal
git tag v0.1.0
git push origin v0.1.0
```

tag 的格式是 `v<major>.<minor>.<patch>`。带后缀的 tag（例如 `v0.2.0-rc.1`）会发布为预发布版本，安装页把它作为预览版，放在最新稳定版旁边。

## 工作流做了什么

`.github/workflows/release.yml` 在每个 `v*` tag 上运行：

1. 从 tag 读出版本：`v0.1.0` 得到 `0.1.0`。
2. 以这个版本作为 `BARRACUDA_VERSION` 构建每块设备开发板，再对它运行 `cargo image package`。开发板按 Rust 目标分组，每个 runner 最多 12 块，分组方式与 CI 相同，都由 `.github/scripts/board-matrix.sh` 给出。主机开发板不发布。
3. 发布每块开发板一个压缩包和 `SHA256SUMS`，附上 GitHub 自动生成的更新说明。

任何一块开发板构建失败都会让整个发布停止，所以一次发布总是包含每块设备开发板。

## 发布里有什么

每块开发板的压缩包 `barracuda-<version>-<board>.tar.gz` 里有一个同名文件夹：

| 文件 | 内容 |
| --- | --- |
| `firmware.bin` | ESP 开发板：bootloader、分区表和应用，从 `0x0` 合并成一个文件 |
| `firmware.elf` | STM32 开发板：应用本身，烧录工具按它自带的地址写入 |
| `resources.img` | 插件资源镜像，写入开发板的 `resources` 区域 |
| `manifest.json` | 版本、开发板、芯片和平台，以及每个文件的偏移、大小和 SHA-256 |

```json manifest.json
{
  "version": "0.1.0",
  "board": "esp32c3-devkitc-02",
  "chip": "esp32c3",
  "platform": "esp32c3",
  "parts": [
    { "path": "firmware.bin", "format": "raw", "offset": 0, "size": 4103760, "sha256": "…" },
    { "path": "resources.img", "format": "raw", "offset": 11141120, "size": 1441792, "sha256": "…" }
  ]
}
```

ESP 的 `firmware.bin` 在第一个应用槽位 `ota_0` 内结束：4 MiB 和 8 MiB Flash 的开发板只有这一个槽位，16 MiB 的开发板有两个（参见[开发板](/zh/boards/overview)中的 ESP Flash 布局）。它的填充部分会擦除 `otadata`，所以即使开发板之前切换到了 `ota_1`，bootloader 也会启动新的应用；它不碰 `kv_database` 和 `system`，所以更新会保留开发板的设置。填充部分也会擦除 `nvs`，Barracuda 不在那里保存任何东西。

只有开发板的分区表与发布版本的相同时，安装页才会保留设置。改变了开发板分区表的发布版本（例如 4 MiB 和 8 MiB 开发板去掉 `ota_1` 的那一版）在装有旧版本的开发板上只能全新安装。

## 固件里的版本

插件 API 中的 `FIRMWARE_VERSION` 是构建时的 `BARRACUDA_VERSION`，没有设置时为 `dev`。

- 开机时，System 打印 `BARRACUDA system=boot board=<board> version=<version>`。
- 设置应用在设备页显示它。
- ESP 固件把它写进应用描述信息（app descriptor），项目名为 `barracuda`。安装页读取 `ota_0` 的应用描述信息，判断开发板上已经装了哪个版本。

## 自己打包一块开发板

按工作流的方式构建并打包一块开发板：

```bash terminal
cargo board select esp32c3-devkitc-02
BARRACUDA_VERSION=0.1.0 cargo build --release
BARRACUDA_VERSION=0.1.0 cargo image package
```

打包结果在 `target/package/barracuda-0.1.0-esp32c3-devkitc-02/`。ESP 开发板需要在 `cargo board select` 之前装好 `espflash`，因为选择开发板时会记录构建所用的 `PATH`。各平台如何生成固件文件，参见[系统镜像](/zh/tools/system-image)。
