title: "官网"
description: "运行、修改和部署 website/ 里的 Barracuda 官网：一个部署在 Vercel 上的静态 Next.js 站点。"
---

官网是 `website/` 里的静态 Next.js 站点，英文版在 `/`，中文版在 `/zh/`。在本地运行：

```bash terminal
cd website
bun install
bun run dev
```

打开 [http://localhost:3000](http://localhost:3000)。`bun run build` 会把静态站点生成到 `website/out/`。

## 文件在哪里

| 路径 | 内容 |
| --- | --- |
| `src/content/en.tsx`、`src/content/zh.tsx` | 网站上的全部文字。两种语言在同一个 pull request 里一起改 |
| `src/content/boards.ts` | 开发板页的列表：`boards/configs/` 里每块开发板一条 |
| `src/components/` | 页面，用 design system 的组件搭成 |
| `src/styles/ds/` | design system 的 `tokens.css` 和 `bundle.css`，原样复制自 design system |
| `src/styles/site.css` | 官网自己的布局，基于 design system 的 token |
| `public/images/` | 油画、品牌 logo 和开发板插图 |

指向文档的链接都通过 `src/lib/links.ts` 生成，每个页面都会链接到读者所用语言的文档。浏览器安装器上线前，所有安装按钮都打开[安装](/zh/get-started/installation)。

## 规则

- 用 design system 的组件（`bc-*`）和 token 来画。官网和文档都要用的组件属于 design system；把它新的 `tokens.css` 和 `bundle.css` 复制到 `src/styles/ds/`，再运行 `bun tools/web/docs-tokens.ts`，让文档跟上。
- 新增开发板时，在 `src/content/boards.ts` 里加上它。列表和 `boards/configs/` 不一致，或列出的开发板没有文档页时，`bun test tools/web` 会失败。

## 部署

Vercel 从这个仓库构建站点：

- **Root Directory**：`website`
- **Framework Preset**：Next.js（自动识别）
- **Production branch**：`master`
- **Include files outside the Root Directory in the Build Step**：打开（默认）

每次推送到 `master` 都会部署站点，每个 pull request 都会得到一个预览链接。

站点还在 `/editor/` 提供 [Live Editor](/zh/apps/live-editor)。`vercel.json` 在 `next build` 之前运行 `apps/live-editor/web/build-site.sh public/editor`：它在构建机器上安装 Rust 和 PocketJS，并把 Live Editor 构建到 `public/editor/`；这个目录不提交。本地的 `bun run build` 不包含 Live Editor。脚本做了什么，见 [Live Editor 内部实现](/zh/tools/live-editor)。
