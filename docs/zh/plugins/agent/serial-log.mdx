把子进程（例如 `idf.py monitor`）输出的完整日志行以流的方式交给逐行回调。默认会去掉 ANSI 颜色，字节解码方式可配置。与框架无关，并且**没有依赖**：你如何产生日志（任何 CLI 命令）以及如何消费这些行（解析器、测试框架、文件），完全由你决定。

```text
[ any command ] --stdout(lines)--> [ LogStream ] --on_log(line)--> [ your code ]
  idf.py monitor                     strips color
  a serial reader                    decodes bytes
  cat device.log                     splits complete lines
```

## 为什么用推送，而不是 `for` 循环

运行中的设备会随时间不断输出日志行。你不需要写阻塞的 `for line in ...`，而是注册一个 `on_log(line)` 回调；一个后台线程读取 stdout 并传递每一个完整的行，让你的主线程保持空闲。

## 安装

```bash
pip install serial-log
```

需要 Python ≥ 3.11。没有运行时依赖。

## 用法

```python
from serial_log import LogStream

def on_log(line: str) -> None:
    print(line)

# Context manager: enter starts the child, exit stops it.
with LogStream(['idf.py', 'monitor'], on_log) as stream:
    stream.wait()        # block until the child exits, or do other work
```

显式的生命周期和多个回调：

```python
stream = LogStream('idf.py monitor')   # str is shlex-split (no shell)
stream.on_log(parser.feed)             # register BEFORE start to not miss lines
unsubscribe = stream.on_log(print)
stream.start()
...
unsubscribe()
stream.stop()
```

## 选项

| 参数 | 默认值 | 含义 |
|----------|---------|---------|
| `command` | — | 程序 + 参数；`str` 会经过 `shlex.split`（POSIX，不经过 shell）。 |
| `on_log` | `None` | 第一个回调，在子进程启动之前注册。 |
| `strip_color` | `True` | 去掉每行中的 ANSI 颜色/控制转义序列。 |
| `encoding` | `'utf-8'` | 用于解码子进程字节的编码。 |
| `errors` | `'replace'` | 解码错误策略；`'replace'` 从不抛出异常。 |
| `cwd` | `None` | 子进程的工作目录。 |
| `env` | `None` | 子进程的环境变量（为 `None` 时继承父进程）。 |
| `merge_stderr` | `True` | 把 stderr 合并进同一个行流。 |

## 语义

- **只传递完整的行**。按 `\n` 分割；末尾的 `\r` 会被去掉，所以
  `\r\n` 和 `\n` 都可以，即使跨越读取边界也一样。没有换行符的最后一行会在 EOF 时发出。
- **背压，而不是丢失**。回调在读取线程上同步运行；慢的回调会让操作系统管道被填满，子进程随之阻塞——不会丢失任何行。
- **失败会暴露出来**。如果回调抛出异常，流会停止读取，终止子进程，并从 `wait()`（或上下文管理器退出时）重新抛出。查看 `LogStream.exception` 获取捕获的错误。
- **只能使用一次**。调用 `start()` 两次会抛出异常；请创建一个新实例。
