Agent Skill 子系统发现说明包，把它们的元数据投射到模型上下文中，并且只在 Agent 请求时才读取包的内容。它负责 skill 的身份和资源包含关系，而文件系统挂载、持久化和镜像组合都在这个子系统之外。

## 边界

~~~text
System-owned VFS
  +-- /workspace/media/skills ----------+
  `-- /workspace/resources/skills ------+--> Skill Registry
                                                |
                                                +--> catalog metadata
                                                +--> SKILL.md reader
                                                `--> bounded resource reader
                                                          |
                                                          v
                                                   Agent skill Tools
~~~

可写的共享 media 根目录包含用户安装的包。共享的 resources
根目录包含由所选插件集合贡献的不可变包。两个根目录提供同一个目录清单，并保留它们现有的文件系统生命周期。

## 目录清单与身份

配置的根目录下的每个直接子目录都是一个 skill 包，以目录名命名，并由它的 `SKILL.md` frontmatter 描述。注册表发布按 skill 名称排序的、不可变的、带版本的目录清单快照。

一个 skill 名称在所有配置的根目录中唯一标识一个完整的包。根目录的顺序不具有选择意义。在两个位置发现同一个名称时，每一份副本都会被排除出目录清单，并连同两个目录一起记录这次冲突，所以用户的包永远不会遮蔽内置的包。

目录清单保留发现所需的元数据和解析出的包目录。
提示上下文只包含名称和描述。文件系统目录始终是注册表内部的细节。

## 渐进式加载

Agent 首先收到精简的目录清单。`skill_read` 加载某个包 frontmatter 下面的 Markdown
说明。说明中可以明确指出其他文件，例如 `references/guidelines.md` 或
`references/examples.md`；`skill_resource_read` 以有上限的 UTF-8 分页加载这些文件。

资源读取器接受一个 skill 名称和一个相对路径。它从当前的目录清单中解析出包目录，只接受路径仍在该目录之内的普通文件。绝对路径、向父目录的遍历，以及由模型提供的文件系统路径都会被拒绝。读取脚本源码并不授予执行它的权限。

调用方可以选择 4 字节到 16 KiB 的分页大小。下限足以容纳任何单个 UTF-8 标量值，上限则让每次读取的分配保持有界。

## 重新加载

重新加载会扫描所有配置的根目录，并在发布之前构造一个完整的替换快照。成功的重新加载会原子地推进目录清单的版本。格式错误的包或重复的名称会被单独排除出新快照，并连同原因一起记录，因为用户的包位于一个共享的可写目录中，一个坏包不能遮蔽其余的包，也不能让 Agent 停下来。无法列出的根目录会让当前快照保持不变，这样现有的 Agent 继续看到一个一致的目录清单。

## 不变式

- skill 名称在所有配置的根目录之间全局唯一。
- 文件系统位置从不在重复名称之间做选择。
- 资源从其目录清单条目所记录的目录中解析。
- 面向模型的资源路径是相对路径，并且被限制在一个包之内。
- 资源读取有上限、分页、只读，并且是 UTF-8。
- 目录清单的重新加载要么发布一个完整有效的快照，要么保留之前的快照。
