应用 API 是可安装应用在不同设备之间都能依赖的东西：它可以使用的 Lua 包、它可以向设备询问什么，以及让两者保持稳定的规则。它分为两部分。本插件的 `app` Lua 包有一个版本，称为 **API 级别**；当前 System 实现的是级别 1，应用在清单的 `api` 中写明它所针对的级别（参见[应用格式](/zh/plugins/app-manager/app-format)）。其他所有 Lua 包则取决于设备注册了什么，每个 Lua 包都会声明自己的承诺。

系统应用不受应用 API 约束：它们随镜像一起提供，可以 `require` 任何 Lua 包。

## Lua 包

注册 Lua 包的插件通过 `LuaPackage::interface` 声明它的承诺，以及该 Lua 包在应用信息界面上显示的那一行说明。本插件从 `LuaPackageRegistry` 读取这些声明；它不会指名任何其他插件的 Lua 包，所以设备向应用提供的，正好是它已启用的插件所注册的内容。每个 Lua 包所属的插件会记录它的函数，以及每个函数是在哪个版本中加入的。

| 接口类型 | 应用如何获得 | 是否在每台设备上都一致 |
| --- | --- | --- |
| 环境（Ambient） | 始终可用，无需请求 | 是 |
| 稳定，带版本 | 在清单的 `requires` 或 `uses` 中写作 `name` 或 `name@version` | 是，只要设备具备 |
| 开发板专用 | `permissions`，配合 `boards` | 否：它直接操作某块开发板的硬件 |
| 无 | `permissions` | 不做任何承诺 |

需要开发板上某个设备的 Lua 包，在开发板缺少该设备时不做任何声明，所以在这样的开发板上，依赖它的应用无法运行。

本插件自己的 Lua 包：

| Lua 包 | 接口类型 | Lua API |
| --- | --- | --- |
| `app` | 环境，版本 1 | 应用本身：事件、视图、存储、`app.device()`（[应用格式](/zh/plugins/app-manager/app-format)） |
| `notify` | 稳定，版本 2 | `notify.post`、`notify.ask`（见下文） |

### `notify`

- `notify.post(title [, body]) -> id` 向通知中心添加一条通知。
- `notify.ask(title [, body [, allow, deny]]) -> allowed` 用一张排在所有通知之前的卡片询问用户，并等待回答：用户允许时返回 `true`，拒绝或关闭时返回 `false`。从版本 2 开始，`allow` 和 `deny` 用来指定卡片上两个按钮的文字（未指定时为 **Allow** 和 **Deny**，每个最多 6 个字符），例如 `notify.ask("Lights on?", nil, "Now", "Later")`。

失败时返回 `nil` 和一条消息。

## 兼容性检查

System 会按以下顺序根据设备检查每个可安装应用，并在遇到第一个原因时停止。`app.list` 把这个原因报告为应用的 `incompatible`；启动器会把该应用变暗显示，它的信息界面会显示原因；`app.open` 返回 `{"error": "incompatible", "reason": …}`。

| 检查项 | 原因说明 |
| --- | --- |
| `api` 高于设备的级别 | `Needs system update (API 2, device has 1)` |
| `boards` 未列出本开发板 | `Only for espressif-esp-vocat-v1-2`（列出的开发板） |
| 应用带视图，而设备没有显示屏 | `This device has no display` |
| 视图是为 `view.target` 以外的显示屏构建的 | `Built for 320×240 display (device has 360×360)` |
| 显示屏小于 `view.size` | `Display too small (needs 480×480)` |
| `requires` 中的某个 Lua 包在本设备上不是稳定 Lua 包 | `This device has no notify` |
| 它在本设备上的版本低于 `requires` 中写明的版本 | `Needs system update (notify v2, device has v1)` |
| `permissions` 中的某个 Lua 包缺失 | `This device doesn't support serial` |

不适配的应用永远不会打开，包括在开发板或系统变化后不再适配的应用。

### 视图与显示屏

视图按显示屏以视图像素计的尺寸布局，宽度从 135 px 到 360 × 360 甚至更大，所以要像写响应式网页那样写视图：

- 用 `w-full h-full` 填满显示屏，用 flexbox 排布内容，不要用绝对定位或固定偏移。
- 给内容 `w-full max-w-[256px]`，而不是固定宽度：在显示屏允许的范围内尽量宽，最宽到设计稿的宽度。
- 文字会像网页上那样按可用宽度在词与词之间换行。行内与其他元素并排的文字用 `flex-1 min-w-0` 占据剩下的空间；用 `basis-[72px] grow min-w-0` 则在空间实在太窄时换到单独一行。和网页一样，文字盒子只有加上 `min-w-0` 才会缩到比最长的词还窄，这时这个词会被拆开。
- 让行使用 `flex-wrap`，这样在窄屏上元素会移到下一行。
- 居中一列内容时，在内容上下各放一个 `flex-1 min-h-0` 的占位元素：在矮屏上占位元素先让出空间，被裁掉的是底部，而不是标题。
- 可能比显示屏更长的列表，放进 `flex-1 min-h-0 overflow-y-auto` 盒子，每行用 `shrink-0`：竖直拖动就能滚动它。加上 `justify-end` 时，它从最后一项开始显示，像聊天记录一样，往上可以滚到第一项。

固定尺寸会保持原样。`view.size` 是视图仍能适配的最小显示屏。设备只按尺寸判断视图：显示屏是圆形还是矩形，由视图的设计来处理，所以面向所有设备的视图要把内容放在圆形显示屏也能显示的区域里。文字保持原有大小：字体字号是按固定的视图像素尺寸烘焙的。开发板可以把每个视图像素画成多个显示屏像素，即它的密度：密度为 2 的 720 × 720 屏幕按 360 × 360 显示视图，画得更清晰，所以视图在它上面看到的尺寸与在 360 × 360 屏幕上相同。需要知道显示屏尺寸的视图可以从 `app.device().display` 读取。为某块显示屏构建的视图（见[应用格式](/zh/plugins/app-manager/app-format)）只在那块显示屏上运行。

## 运行

可安装应用的运行可以 `require` 环境 Lua 包，以及清单在 `requires`、`uses` 和 `permissions` 中列出的每个 Lua 包。应用未列出的 Lua 包不可用，`require` 会失败。`uses` 中的 Lua 包可能缺失，或者版本比应用期望的旧：在 `require` 之前先检查 `app.device().capabilities`，或者调用 `pcall(require, name)`。

`app.device()` 描述设备；`capabilities` 把每个稳定 Lua 包映射到它的版本：

```lua
{
  api = 1,
  board = "espressif-esp-vocat-v1-2",
  display = { width = 360, height = 360, density = 1 },  -- nil without one
  touch = true,
  capabilities = { notify = 2, ... },
}
```

## 版本管理

- 稳定 Lua 包的接口一经声明就永不改变：不会删除或重命名任何函数，也不会改变其参数或返回值。
- 添加函数会提升 Lua 包的版本；其插件会记录每个版本新增了什么。
- 不兼容的变更会成为一个新名称的新 Lua 包；旧的 Lua 包保持不变。
- `app` Lua 包遵循同样的规则，以 API 级别作为它的版本。
- 开发板专用的 Lua 包，或者不做任何承诺的 Lua 包，可能随任何系统更新而变化；这正是使用它们的应用需要列出适用开发板的原因。
