`pocketjs-core/` 和 `microts/` 复制自 [PocketJS](https://github.com/pocket-nexus/pocketjs) 的提交 `96e5f4084c2da45d72997c443fd478bcffb92dc7`：

| 目录 | 上游路径 |
| --- | --- |
| `pocketjs-core/src` | `engine/core/src` |
| `microts/src` | `engine/crates/microts/src` |

两者都采用 MIT 许可证（每个目录下都有 `LICENSE`）。库源码未做修改，只是删除了三个测试模块，因为它们会从 PocketJS 仓库读取测试夹具：独立文件 `core/src/tests.rs` 和 `core/src/physics/tests.rs` 及其 `mod tests;` 声明，以及 `core/src/package.rs` 末尾的内联 `mod tests`。另有一行不同：`microts/src/model.rs` 在所有目标上都从 `portable_atomic` 引入 `AtomicU32` 和 `Ordering`，而上游在支持 32 位原子操作的目标上从 `core::sync::atomic` 引入，这样同一行引入也能用于 ESP32-C3。源码还用本工作区的 `rustfmt` 重新格式化过。清单文件经过改写，可以在本工作区中独立使用，并关闭了 Clippy 的风格类 lint。

`pocketjs-core` 还带有对 PocketJS 本身的修改，每一项都连同原因记录在 `pocketjs-core/patches/` 中，按文件名顺序应用：

| 补丁 | 修改 |
| --- | --- |
| `0001-soft-wrap.patch` | **文字换行。** 上游只在 `\n` 处断行。`Ui::set_soft_wrap` 让布局在同一次求解中按盒子得到的宽度为文字换行，并让绘制按这些行来画。它默认关闭；UI 运行时为每个视图打开它。 |
| `0002-scroll.patch` | **滚动容器。** 上游在 JS 中实现滚动。`Overflow::Scroll` 像 `overflow-hidden` 一样裁剪，并按宿主驱动的偏移量（`Ui::set_scroll`）移动内容，绘制和点击检测都一样，偏移量限制在上次布局得出的范围内（`Ui::scroll_bounds`）；`Ui::set_scroll_bar` 显示滚动指示条。UI 运行时根据触摸驱动它。 |

不使用这些功能的视图不受任何影响。滚动修改在编译器一侧的部分，即 `overflow-y-auto` 和 `overflow-y-scroll` 两个 class，在 `plugins/app-manager/resources/pocketjs/overflow-scroll.patch` 中。

更新时，从较新的提交复制同样的路径，重新执行这三处删除和 `portable_atomic` 引入，运行 `cargo fmt --all`，再在 `pocketjs-core/src` 中用 `patch -p1 < ../patches/<补丁>` 逐个应用补丁。上游合入某项修改后，删除对应的补丁。`plugins/app-manager/resources` 中的构建脚本使用同一提交的 PocketJS 检出来编译视图：它们先复制一份并应用 `resources/pocketjs/` 中的补丁，所以检出本身不会被改动；为某块显示屏构建时，用这个打过补丁的核心和检出中 `engine/wasm` 的绑定一起构建为 WebAssembly，再求解矩形。不要把 Barracuda 专用的代码放进这些目录；它们应该放在 `barracuda-ui-runtime` 中。
