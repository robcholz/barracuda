GPIO 插件把开发板可用引脚上的数字输入和输出作为 `gpio` Lua 包暴露给 Lua 代码。

- 插件 ID：`gpio`
- 依赖：`vm`
- 设置：无
- 上下文资源：`hal.exposed_io`
- 提供的能力：无
- 所需能力：来自 `vm` 的 `LuaPackageRegistry`
- Workflow：无
- Agent 工具：无
- Lua 包：`gpio`
- Web：无
- 任务：无
- 存储：无

在统一的插件构造期间，本插件共享开发板唯一的运行时 I/O 所有者。注册期间，它在 VM 注册表中安装只能 require 的 `gpio` Lua 包。

Lua API：

- `gpio.available(name) -> boolean`
- `gpio.open_input(name, pull) -> handle`，其中 pull 为 `none`、`up` 或 `down`
- `gpio.open_output(name, initial_high, drive) -> handle`，其中 drive 为 `push-pull` 或 `open-drain`
- `handle:read() -> boolean`
- `handle:write(high)`
- `handle:is_open() -> boolean`
- `handle:close()`

打开操作会从统一 I/O 所有者上的某个提供者那里获得一个独占的数字占用。返回的引脚实现了 `ConfigurableDigitalPin` 和标准的 `embedded_hal::digital` trait。无效的名称、忙碌的引脚、不支持的电气模式以及引脚故障都使用 Lua 惯用的 `nil, error` 结果。显式关闭、词法 `<close>`、userdata 回收以及 Lua 状态销毁都会禁用并释放句柄。生成的设备所有者保留了厂商 HAL 的令牌只能移动的规则，所以物理引脚在重启之前一直处于被占用状态，而不会在关闭后被不安全地重新构造。

丢弃 Lua 包的注册会撤销回调，并使已经安装到 Lua 状态中的句柄上的操作失效。
