基于开发板的 LED 灯带安装 `light` Lua 包，默认使用主灯带。

- 插件 ID：`led-strip`
- 依赖：`vm`
- 设置：无
- 上下文资源：外设槽位 `led-strip.devices`（`*`）
- 提供的能力：无
- 所需能力：来自 `vm` 的 `LuaPackageRegistry`
- Workflow：无
- Agent 工具：无
- Lua 包：`light`
- Web：无
- 任务：无
- 存储：无

本插件获取开发板上没有被其他插件占用的每个 `LedStrip`，主灯带排在最前，并安装 `light` Lua 包。它使用的是语义层面的外设能力，从不暴露或重新构造它的 SPI 或 RMT 传输。

Lua API：

- `light.list() -> { name, ... }`：各LED 灯带在开发板上的名称，主灯带排在最前
- `light.available([name]) -> boolean`：指定名称的LED 灯带（不给出时为主灯带）能否打开
- `light.open([name]) -> handle`：打开指定名称的LED 灯带，不给出时打开主灯带
- `light.fill(color[, name]) -> true` 把指定名称的灯带（不给出时为主灯带）的每个像素设为 `color`，取值为 `"#RRGGBB"`，或 `white`、`warm`、`red`、`green`、`blue`、`off`、`black` 之一
- `light.off([name]) -> true` 关闭指定名称的灯带（不给出时为主灯带）的每个像素
- `handle:len() -> integer`
- `handle:write(rgb_bytes)`，其中每个像素是三个连续的 RGB 字节
- `handle:clear()`
- `handle:is_open() -> boolean`
- `handle:close()`

当开发板具备该设备时，这个 Lua 包声明一个稳定接口（`PackageInterface::Stable`），版本 3；版本 2 加入了 `light.fill` 和 `light.off`，版本 3 加入了 `light.list` 和灯带名称。

从版本 2 开始提供的 `fill` 和 `off` 在没有句柄占用灯带时使用它，在有句柄占用时返回 `nil, error`。

没有内置 LED 灯带的开发板仍然会安装这个 Lua 包；`available` 返回 false，`open` 返回 `nil, error`。每个灯带同一时间只能打开一个句柄：显式关闭、词法 `<close>` 和垃圾回收都会阻止对它的后续操作，并归还灯带，所以 `open` 可以再次使用；插件被撤销会阻止所有后续操作。
