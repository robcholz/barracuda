基于开发板的电源监测器（由 `power` 插件拥有）安装 `power_monitor` Lua 包，默认使用主监测器。

- 插件 ID：`power-monitor`
- 依赖：`vm`、`power`
- 设置：无
- 上下文资源：无
- 提供的能力：无
- 所需能力：来自 `vm` 的 `LuaPackageRegistry`，来自 `power` 的 `Power`
- Workflow：无
- Agent 工具：无
- Lua 包：`power_monitor`
- Web：无
- 任务：无
- 存储：无

本插件基于 `Power` 安装 `power_monitor` Lua 包。监测器、它们的驱动以及提供给其他插件的电池电量，都归 `power` 插件所有。

Lua API：

- `power_monitor.list() -> { name, ... }`：各监测器在开发板上的名称，主监测器排在最前
- `power_monitor.available([name]) -> boolean`：指定名称的监测器（不给出时为主监测器）是否存在且可以打开
- `power_monitor.open([name]) -> handle`：打开指定名称的监测器，不给出时打开主监测器
- `handle:measure() -> bus_microvolts, shunt_nanovolts, current_microamps, power_microwatts`
- `handle:battery() -> percent, charging`；不是电池电量计的监测器不返回任何值
- `handle:name() -> string`：监测器在开发板上的名称
- `handle:is_open() -> boolean`
- `handle:close()`

主监测器是产品的主要监测器，通常是电池的，所以不指定监测器的脚本在每块开发板上读取的都是电池。开发板的其他监测器，例如 M5Stack Station 的 Grove 端口监测器（`port-a1-power` 到 `port-c2-power`），按名称打开。

`measure` 读取一次一致的采样。总线电压为正；分流电压、电流和功率带符号，按监测器 IN+ 到 IN- 的方向为正。测量失败时返回 `nil, error`。

```lua
local power_monitor = require('power_monitor')
for _, name in ipairs(power_monitor.list()) do
  local monitor <close> = assert(power_monitor.open(name))
  local bus_uv, _, current_ua = assert(monitor:measure())
  print(string.format('%s: %.3f V %.1f mA', name, bus_uv / 1e6, current_ua / 1e3))
end
```

没有电源监测器的开发板仍然会安装这个 Lua 包；`list` 为空，`available` 返回 false，`open` 返回 `nil, error`。每个监测器每次开机只能打开一个句柄；显式关闭、词法 `<close>`、垃圾回收和插件被撤销都会阻止后续操作。开发板有监测器时，这个 Lua 包声明一个开发板相关的接口（`PackageInterface::BoardSpecific`），因为每个监测器测量什么取决于开发板的接线。

句柄通过共享的 `Power` 读取，所以句柄打开期间其他插件仍可读取监测器。本插件不做后台采样，也不拥有长时间运行的任务。
