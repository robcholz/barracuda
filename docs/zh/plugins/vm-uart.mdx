基于开发板的可用 I/O 引脚安装 `uart` Lua 包。

- 插件 ID：`uart`
- 依赖：`vm`
- 设置：无
- 上下文资源：`hal.exposed_io`
- 提供的能力：无
- 所需能力：来自 `vm` 的 `LuaPackageRegistry`
- Workflow：无
- Agent 工具：无
- Lua 包：`uart`
- Web：无
- 任务：无
- 存储：无

本插件共享开发板统一的可用 I/O 所有者，并安装 `uart` Lua 包。端口实现了 `embedded_io_async::Read + Write`；控制器分配和引脚路由留在平台提供者内部。

Lua API：

- `uart.available(tx, rx) -> boolean`
- `uart.open(tx, rx, baud, data_bits, parity, stop_bits[, de]) -> handle`
- `handle:read(max_length) -> bytes`
- `handle:write(bytes)`
- `handle:flush()`
- `handle:is_open() -> boolean`
- `handle:close()`

`tx` 或 `rx` 可以为 `nil`，但不能两者都是。数据位为 `7`、`8` 或 `9`；校验为 `"none"`、`"even"` 或 `"odd"`；停止位为 `1` 或 `2`。打开操作会从其他可用协议所用的同一个所有者那里原子地取走每一个所选的物理引脚。

对于 RS485 收发器，`de` 指定使能其驱动器的引脚（通常标为 DIR 或 DE/RE）。此时端口在每次写入时拉高该引脚，等到最后一个停止位从 UART 发出后再拉低，因此收发器在其他时间都处于接收状态；`de` 需要同时有 `tx` 引脚。带 RS485 接口的开发板会暴露它的三个引脚，例如 `rs485-tx`、`rs485-rx` 和 `rs485-dir`：

```lua
local uart = require("uart")
local bus <close> = uart.open("rs485-tx", "rs485-rx", 9600, 8, "none", 1, "rs485-dir")
bus:write("\x01\x03\x00\x00\x00\x01\x84\x0a")
local reply = bus:read(7)
```
