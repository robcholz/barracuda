Barracuda 设备能做的一切都来自插件。运行时本身很小：一个可移植的 System，按依赖顺序注册插件并统一启动它们。定制设备、在设备上构建、扩展设备，归根结底都是选择、配置、精简或编写插件。

## 插件是什么

插件是一个自包含的单元，拥有稳定的标识和声明式的契约。

- **标识和依赖。**`plugin.toml` 定义插件的 ID、它依赖的插件以及它的构建任务。
- **类型化能力**。插件可以向其他插件提供领域 API，也可以依赖其他插件的 API。插件之间就是这样直接协作的。
- **Workflow Action 和 Event**。插件可以通过稳定且经过 schema 校验的契约，把操作和事实暴露给 Workflow 自动化。
- **Agent Tool**。插件可以通过专为 Agent 设计的面向模型的工具，为板上 Agent 提供新能力。
- **VM 包**。插件可以把硬件或服务暴露给脚本，让板上 Agent 即时编写的代码可以使用它们。
- **门户页面**。插件可以为设备门户贡献自己的页面、图标和状态，让每项能力都自带设置。
- **资源和存储**。插件拥有自己的文件、设置和长期运行的任务，并在停止时释放它们。
- **文档**。每个插件都在自己的 `docs/plugin.md` 中记录它的能力、工具、Action、Event、错误和生命周期，读者既包括人，也包括 Agent。

## 为什么作为基本单元

- **添加任何东西只有一种方式**。传感器驱动、消息通道、网页搜索服务，乃至 Agent 本身，全都是插件。不需要学习第二种扩展机制。
- **可组合**。插件依赖的是彼此的能力，而不是彼此的内部实现，所以可以自由组合。
- **可移除**。未启用的插件不会被打包。移除一个插件就会释放它的内存、Flash 和任务。
- **可移植**。插件依赖可移植的服务，从不依赖某款特定芯片，所以同一个插件可以在每个平台上运行。
- **对 Agent 友好**。契约足够明确，Agent 可以读懂、使用和编写。板上 Agent 调用插件的工具；编程 Agent 用 `create-plugin` skill 创建插件。

## 插件目录

| 类别 | 示例 |
| --- | --- |
| 设备 | Wi-Fi 配网和设置热点、Web 服务器、设备门户、HTTP 客户端、时间、调度器 |
| Agent | 板上 Agent、网页搜索、文件、面向 Agent 的 HTTP、定时任务、Workflow 访问、VM 访问 |
| 消息通道 | 微信、Telegram、QQ、iMessage、Inkbox、网页聊天、终端 |
| 自动化 | Workflow、调度器 |
| 脚本 | VM 及其包 |
| 外设 | GPIO、模拟、I2C、I2S、SPI、UART、PWM、显示屏、摄像头、音频、IMU、LED 灯带、电源监测、文件系统、消息队列、系统信息 |
| 应用 | App Manager 和应用运行时 |

## 用插件定制

| 谁 | 如何定制 |
| --- | --- |
| 用户和创客 | 在自己的电脑上选择插件集合并构建；在设备门户中配置每个插件 |
| 应用开发者 | 通过 Live Editor 在应用中使用插件 |
| 插件开发者 | 用 `create-plugin` 创建新插件 |
| 构建者 | 为产品选定精确的插件集合，并用 `fully-customize` 把每个插件精简到目标的预算之内 |

## 适配资源

Barracuda 可以运行在只有几百 KB RAM 的微控制器上、带外部内存的开发板上，以及桌面主机上。插件集合是适配目标的主要手段：

- 小型目标只带必需品：网络、门户、Agent、VM、一个消息通道；
- 大型目标可以加上外设、更多消息通道、应用和并发脚本；
- 产品固件只带产品需要的东西，别无其他。
