## 定位陈述

对于想要 AI 原生设备、又不想背负嵌入式工具链负担的开发者、教育者和开发板公司，Barracuda 是一个基于插件的嵌入式运行时和 Agent 平台。云端助手把设备当作一个扬声器加一个麦克风，传统的嵌入式 SDK 让每个项目都从零开始；Barracuda 与它们不同，它在设备上放置一个实时为硬件编程的 Agent，并为构建者提供完成其他一切的 Agent——在浏览器中构建应用；在自己的电脑上构建插件、开发板和固件。

## 一句话介绍

**Barracuda 是面向嵌入式设备的 Agent 平台：一切都是插件，每一步都有 Agent 帮忙。**

## 标题备选

- 每块开发板，都有 Agent。
- 面向嵌入式的 Agent 平台。
- 从一句话到一个固件，每一步都有 Agent。
- 每台设备上都有一个 Agent。你为它构建的一切，都有 Agent 相助。

## 核心信息

1. **设备上的 Agent。**每台 Barracuda 设备都带有一个轻量的 Agent，实时为自己的硬件编程：提出一个涉及物理世界的请求，看着它编写脚本并运行。
2. **插件是基本单元。**每项能力都是一个插件。选择插件、用插件构建、编写你自己的插件，只交付你需要的部分。
3. **每一级都有 Agent。**浏览器里的 Agent 构建应用；编程 Agent 借助 Barracuda 的 skill 创建插件、开发板、平台和定制固件。
4. **嵌入式上的现代开发体验。**从浏览器安装，在网页上配置，在手机上聊天；当你深入时，只需一个仓库、一条命令，以及你已经在用的编程 Agent。
5. **在你需要的地方运行。**同一个 System 运行在 ESP32 和 STM32 微控制器上，也运行在 Linux 和 macOS 上，并适配每个目标的资源。

## 佐证

- 一个可移植的 System，横跨微控制器和桌面主机。
- 数十个官方插件：网络、门户、Agent、脚本 VM、Workflow、消息通道，以及从 GPIO 到摄像头的各种外设。
- 来自 M5Stack、Espressif、ST 等厂商的开发板，可从浏览器安装。
- 仓库中提供面向 Claude Code、Cursor 和 Codex 的 skill。
- 每个插件都有面向人和 Agent 的文档。

## 面向每类用户的说法

| 用户 | 开场 | 然后 |
| --- | --- | --- |
| 创客 | “和你的开发板对话；它编写代码并运行。” | 从浏览器安装、选择插件 |
| 应用开发者 | “描述一个设备应用；得到它和它的 UI；从浏览器烧录。” | Live Editor、App Manager |
| 插件和运行时开发者 | “你的编程 Agent 按 Barracuda 的方式构建 Barracuda。” | skill、插件契约、每个目标上同一个 System |
| 构建者 | “交付适配你的芯片和任务的固件。” | `fully-customize`、可移除的插件 |
| 教育 | “第一天就从一句话走到硬件，学期结束时从脚本走到系统。” | 无需配置，阶梯即课程 |
| 开发板公司 | “让你的开发板为 AI 做好准备，并可从浏览器安装。” | `create-board`、在网页安装器中上架 |

## 用词

| 使用 | 避免 | 原因 |
| --- | --- | --- |
| Agent 平台、嵌入式运行时 | AI 助手、聊天机器人、智能音箱 | Barracuda 是用于构建的平台，而不是单个助手 |
| 板上 Agent | 云端 AI、语音助手 | Agent 运行在设备上 |
| 即时编程、编写脚本并运行 | 生成代码（不加限定） | 区分运行时脚本和构建时生成 |
| 插件 | 模块、附加组件、扩展 | 插件是基本单元，也是定义好的术语 |
| 从浏览器安装 | 烧录固件（在面向外部的页面上） | 面向新手的结果性语言；在开发者文档中说“烧录”没有问题 |
| 开发板、平台 | 设备类型、SDK | 定义好的术语；开发板和平台各自独立选择 |
| 面向 Claude Code、Cursor 和 Codex 的 skill | AI 集成 | 点出开发者已经在用的工具 |

在面向外部的页面（网站、安装器、门户）上，描述结果。把内部细节——Lua、应用运行时的语言、执行器和栈的细节——留在开发者文档中，在那里它们才有帮助。
