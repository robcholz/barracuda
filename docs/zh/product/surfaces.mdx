Barracuda 是一个产品，通过多个界面被人们使用。每个界面只有一项职责，并把用户交接给下一个界面。

```text
Website ──► Web Installer ──► Device Portal ──► Channels
   │              │                 │
   │              └──► Live Editor (build apps, flash)
   │
   └──► Docs ──► Repository + skills (coding agents on the developer's machine)
```

## 网站

**职责**：用一分钟讲清 Barracuda 是什么，并把每位访客送到正确的第一步。

网站讲的是结果，而不是内部细节。它介绍基于插件的运行时、每台设备上的 Agent，以及从开箱即用到完全定制固件的阶梯。它按意图为人们指路：安装开发板、构建应用、阅读文档、作为开发板厂商合作，或者把 Barracuda 带进课堂。

## 网页安装器

**职责**：在几分钟内，从浏览器把一块空白开发板变成在线状态。

1. 选择开发板和版本。每块开发板都有一个默认固件，带有默认的插件集合。
2. 通过 USB 连接；安装器识别芯片以及任何已有的安装。
3. 安装，并提供清晰的进度显示和恢复手段。
4. 通过同一个 USB 连接加入 Wi-Fi。
5. 交接给设备门户。

网页安装器也是浏览器工具集的第一步：之后，同一个连接会烧录在 Live Editor 中构建的应用。

## 设备门户

**职责**：从本地网络中的任意浏览器配置和了解设备。

门户由设备提供。它显示设备的状态以及设备运行的插件。每个插件都贡献自己的页面：Wi-Fi、模型、网页搜索、每个消息通道、文件，以及新插件添加的任何内容。用户在这里配置每个插件，设备的网页聊天也在这里。

## 消息通道

**职责**：在用户已经在用的地方触达板上 Agent。

微信、Telegram、QQ、iMessage、Inkbox、设备的网页聊天和终端，都是通往同一个 Agent 的消息通道，共享同样的会话。每个消息通道都是一个插件。

## Live Editor

**职责**：借助 Agent，以可视化方式构建设备应用并烧录它们。

开发者描述一个应用；浏览器里的 Agent 生成它的逻辑和 UI；开发者实时预览和迭代；浏览器烧录结果。应用在设备上由 App Manager 插件管理，并通过与系统其余部分相同的契约使用设备的插件。

## Skill

**职责**：让编程 Agent 按 Barracuda 的方式构建 Barracuda。

skill 位于仓库中，由 Claude Code、Cursor 和 Codex 读取。它们涵盖创建插件、开发板和平台，以及组合完全定制的固件。skill 是运行时开发的主要接口；它们所编码的约定，正是人类贡献者遵循的同一套约定。

## CLI

**职责**：为开发者提供快速的迭代循环。

`cargo board select` 选择开发板；`cargo run` 构建、烧录并运行；`cargo image deploy` 写入插件资源；`cargo plugin run build` 构建插件页面；`cargo cli` 把一个终端消息通道连接到正在运行的设备。

## 文档

**职责**：作为阶梯每一级的参考，人和 Agent 都能阅读。

文档按层级组织——开箱即用、配置、构建应用、创建插件、开发板和平台、完全定制——并为每个插件、命令和文件格式提供参考部分。每个页面都可以复制为 Markdown 或在 AI 助手中打开，文档也会作为上下文提供给编程 Agent。
