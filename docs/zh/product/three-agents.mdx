Barracuda 把 AI 放在三个位置。每个位置都对应它最擅长的工作，而且三者都以插件作为能力单元。

|  | 板上 Agent | 浏览器里的 Agent | 本机编程 Agent |
| --- | --- | --- | --- |
| 所在位置 | 设备上 | Live Editor 中 | 开发者的电脑上（Claude Code、Cursor、Codex） |
| 工作时机 | 运行时 | 构建时 | 构建时 |
| 做什么 | 即时编程：编写 VM 脚本，立即驱动硬件 | 应用开发：生成设备应用及其 UI | 创建插件、开发板、平台；组合出完全定制的固件 |
| 量级 | 轻量，受设备资源限制 | 重量级，完整的模型和上下文 | 重量级，完整的仓库和工具链 |
| 产出 | 立即运行的脚本 | 烧录到设备上的应用 | 构成固件的源代码 |
| 阶梯层级 | 1 | 3 | 4、5、6 |

## 板上 Agent：即时编程

板上 Agent 以 Agent 插件的形式在设备上运行。它负责会话、记忆、计划、子 Agent、skill 和工具；只有模型推理是远程调用，发往用户配置的模型服务商或 Barracuda 的模型服务。用户可以通过任意消息通道访问它：微信、Telegram、QQ、iMessage、设备的网页聊天或终端。

它的标志性能力是**即时编程**。当请求涉及物理世界时，Agent 会编写一段简短的 Lua 脚本，在设备上的 VM 中运行。VM 包暴露了各种硬件（GPIO、I2C、SPI、UART、PWM、模拟输入、显示屏、摄像头、音频、IMU、LED 灯带、电源监测），所以脚本一运行就能读取并驱动真实的外设。脚本可以在运行中向用户索要输入、报告进度，也可以被列出或取消。脚本还可以反过来向 Agent 提问，因此运行中的程序也能进行推理。

对于必须在对话结束后继续存在的行为，Agent 会使用 Workflow 自动化和定时任务：“每天早上七点”“按下按钮时”“温度超过 30°C 时”。

**为什么刻意保持轻量。**设备的内存预算是固定的，执行槽位也很少。板上 Agent 的任务不是构建软件，而是用设备现有的能力迅速、安全、可见地行动。更大的工作都放到构建时完成。

## 浏览器里的 Agent：应用开发

浏览器里的 Agent 位于 Live Editor 中。开发者描述一个应用；Agent 生成它的逻辑和 UI，开发者在实时可视化预览中细化。准备就绪后，浏览器通过 USB 把它烧录到设备上。

在设备上，应用由 App Manager 插件管理，与其他所有插件一起在应用运行时中运行。应用通过与系统其他部分相同的契约使用设备的插件，所以应用可以使用显示屏、传感器、网络和板上 Agent。

**为什么放在浏览器。**生成应用受益于大模型、大上下文和可视化循环：生成、预览、调整。浏览器三者兼备，无需安装，而且它本来就持有用于烧录的 USB 连接。

## 本机编程 Agent：插件、开发板、平台、固件

创建运行时代码（插件、开发板、平台和定制固件）的工作在开发者的电脑上、在 Barracuda 仓库中进行，使用开发者已经在用的编程 Agent：Claude Code、Cursor 或 Codex。

Barracuda 为这些 Agent 提供了 **skill**。skill 记录了 Barracuda 的构建方式，让 Agent 按 Barracuda 的方式做事：

| Skill | Agent 用它做什么 |
| --- | --- |
| `create-plugin` | 创建或更新插件：选择类型化能力、Workflow Action 与 Event 或 Agent Tool；接好生命周期和任务归属；编写 schema、文档和聚焦的测试 |
| `create-board` | 在已有平台上添加开发板：芯片、目标、Flash 布局、外设 |
| `create-platform` | 在平台契约之下适配新的芯片系列，不改动 System 或插件 |
| `fully-customize` | 选择或创建平台和开发板，挑选并精简插件，创建缺失的插件，让固件适配目标的资源 |

**为什么放在本机。**这类工作需要完整的源码树、原生工具链、构建、测试，常常还需要桌上的硬件。这样的环境就是开发者的电脑，而最适合它的 Agent 正是开发者已经信任的编程 Agent。

## 三者如何协作

- **沿阶梯向下：**构建者的定制固件自带板上 Agent；在 Live Editor 中构建的应用可以调用板上 Agent；在电脑上创建的插件可供脚本、应用和设备门户使用。
- **沿阶梯向上：**在设备上验证了某个想法的脚本，可以在 Live Editor 中变成应用；需要运行时缺少的能力的应用，会变成插件；需要新硬件的插件，会变成开发板。
- **底层是同一份契约：**三种 Agent 都通过插件契约工作：设备上的 Agent Tool、编辑器中的应用接口，以及仓库中的插件、开发板和平台契约。正是这份共享的契约，让工作可以在它们之间流转。
