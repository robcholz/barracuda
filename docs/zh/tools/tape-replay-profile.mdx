## 工作负载

`overall-capabilities.jsonl` 包含 11 个录制的响应和 1,212 个原始响应数据块。`tape-replay` 场景重建了所有响应，并以七字节读取的方式把它们送入生产环境中的 OpenAI 流式栈。这有意代表一种碎片化/抖动的压力情况，而不是典型的套接字合并读取。

## DHAT 摘要

| 指标 | 值 |
| --- | ---: |
| 分配总次数 | 394,897 |
| 分配总字节数 | 21,027,390 |
| 峰值存活分配数 | 34 |
| 峰值存活字节数 | 3,260,587 |
| 保留分配数 | 41 |
| 保留字节数 | 1,799,905 |

最主要的高频位置是脚本化传输中的字节复制（164,988 个块）、`eventsource-stream` 的 UTF-8 累加器增长（164,968 个块），以及它的事件解析器中的 `String::split_off`（25,592 个块）。第一项是性能分析夹具的开销；后两项表明，非常小的网络读取会放大 SSE 层中的分配/释放抖动。

分配量最大的位置是 UTF-8 累加（3.38 MiB）、响应向量构造（3.16 MiB）和 SSE 事件拆分（2.88 MiB）。加载录制带本身临时分配了 1.67 MiB。运行结束时，重建的响应体中仍保留 1.58 MiB，脚本化网络保留的请求捕获中约有 204 KiB。这些保留的字节属于测试框架，不得解读为生产环境 Agent 的泄漏。

## 后续工作

在修改生产代码之前，先用真实的套接字读取大小再做一次分析。如果 SSE 抖动仍然突出，首先研究在 UTF-8/事件边界使用有界的可复用缓冲区，而不是优化 Agent 会话层。只测量稳态解析时，把录制带加载和响应构造排除在 DHAT 的测量范围之外。
